# 资料查询视图

从“资料与状态”进入“组合查询与待办”，先组合已有筛选，再运行查询。查询读取当前 Project 缓冲；资料结果、来源和命中原因均由 core 提供。

宽窗口可点击“名称”或“对象类型”表头排序，再次点击同一列切换方向。结果区的“排序”菜单始终显示当前状态，窄窗口也可使用；“默认顺序”恢复既有对象类型、ID、来源与行号顺序。名称与类型之间只选择一个主字段，不叠加多字段排序。

名称采用忽略 ASCII 大小写的 Unicode 顺序，不是拼音顺序或数字自然排序；例如“10”位于“2”之前。空白名称显示“未命名”，升降序均置后。对象类型指 character/entity/tag 等稳定标识，不是实体自定义分类。主键相同时按固定对象身份和来源排序，降序不反转并列对象。

先对全部命中排序，再显示当前页。切换排序从第一页重新运行；当前缓冲改变后须重新查询。点击名称仍打开该完整对象，点击来源定位声明；同名对象不合并，命中原因可逐项展开。清空筛选条件保留当前排序。

浏览、改变排序、分页和取消不写入作品。只有“保存共享定义”将排序放入已有查询展示文档；再次打开工程并载入定义可恢复。个人收藏仍只保存在本机。若要移除排序能力，选择“默认顺序”后显式保存定义；含对象引用条件的查询仍保留 v3 和引用值能力，须另外显式删除这些条件。

无对象引用条件时，排序查询版本为 2，默认查询为 1；对象引用条件使用显式查询 v3，page/cursor 版本不变。未知字段、方向或版本不自动忽略，未知文档保留原字节。只读工程仍可查询，保存须遵守现有只读保护。此视图不改变源码次序、故事执行或运行指纹。

## 0.8 个人展示列

“显示列·个人”可勾选实体分类、标签和最多六个已存在property键，调整这些列的顺序。宽视图横向滚动，窄视图以同样字段显示在结果卡片中。列设置保存在当前设备并按工程区分，翻页/排序不丢，不写共享查询或工程文档。未设置、空字符串、false和0明确区分；ref显示完整身份。名称/对象类型排序仍沿原核心语义；属性列不提供属性排序、分组、公式或批量改稿。

## 0.29 对象引用属性的精确查询

在“属性值”条件中选择“对象引用（需查询 v3）”，选择 entity、relation 或 character，再填写完整稳定 ID，按“添加属性值”。仅切换输入类型不升级查询；显式添加第一个引用值时由 core 将查询设为 v3，删除最后一个引用值后按现有排序恢复 v1 或 v2。载入、浏览、运行旧定义不迁移版本。

引用条件按 kind 与 ID 完全相等。显示名、别名、相似 ID 和普通字符串“entity:target”不会被当成同一引用。不存在但合法的目标允许添加并返回零命中；非法 ID、未知类型和空 ID 不可提交，错误来自 core 验证。既有声明的 END 身份可以查询。人物引用是否属于有效源码仍受工程原有 1.13 与人物引用能力保护；查询不升级语言或产生关系事实。

“文字”类型允许显式添加空字符串，条件标签显示“空字符串”；一个空格、多个空格显示带引号的原值，输入不去空格。数字空输入不可提交，0 与 false 均为各自类型的实际值。“缺少属性”只表示属性键不存在，不等同于空字符串、空格、0、false 或引用。同维度多个值按 OR，跨维度按 AND；“排除此条件”否定整个 OR 集合，也包含没有该属性的对象。若只查已有属性，应再加“缺少属性”并勾选排除。

保存仍通过现有共享查询事务，外层文档 schema 保持 1。引用值声明文档级 catalog.query_reference_values.v1；含排序时同时保留 catalog.query_sort.v1，工程清单继续只登记 catalog.saved_queries.v1。显式移除引用并保存只移除本功能能力，未知可选扩展继续保留。缺少能力、未知版本或必需能力的定义不能载入编辑或执行，原字节保持；外部冲突、过期基线和只读文档继续由 core 拒绝写入。

查询结果、分页和引用条件不改变源码、故事运行指纹或删除影响。更改条件的 kind、ID、排序或当前稿会使旧页过期；共享查询中的引用身份参加既有安全改名，普通字符串与扩展字段不会跟随改写。
