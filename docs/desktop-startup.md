# 桌面启动与新建作品

本文对应 worldedit 0.36.1 的桌面入口。编辑器可以在没有作品时启动，语言、源码分析和保存仍由配对的 worldline core 提供。默认语言为 1.9，最高显式语言为 1.13；启动不会升级作品语言。

## 直接启动

解压 Windows 发行包，双击 `worldedit.exe`。无参数时尝试恢复有效的最近工程；首次使用、没有最近工程或最近路径失效时显示“欢迎使用 worldedit”。欢迎页提供“新建作品”“打开工程”“外观设置”和“退出”；有失效最近记录时还提供“重试上次工程”。Ctrl/Cmd+N 或 Ctrl/Cmd+O 可进入对应路径对话框。浏览或关闭欢迎页不创建作品，不自动写入演示内容，也不要求保存临时占位工程；设备外观等个人偏好仍按原有规则保留。

安装目录、源码仓库和作品目录应分别存放。不要把解压后的程序目录选作新作品目录。

```powershell
./worldedit.exe
```

## 新建作品

1. 点击“新建作品”
2. 输入尚不存在的新文件夹完整路径，例如 `D:/作品/我的世界`；也可用可选系统选择器选一个已有空目录
3. 核对位置，点击“创建作品”
4. 创建成功后进入工程；空白 `world.wl` 只有 `event start` 与结束指令，不预填人物、正文、地图、书稿或样例
5. 要写正文，进入“书稿”并按[从空白作品开始写作](start-writing-0.30.md)创建书名、章名与正式正文来源

确认创建才写入文件。非空目录、不可写位置和其他无效目标会明确报错，不接管或覆盖其中内容；保留路径输入，可修改后重试。取消应用内对话框返回欢迎页或原工程；取消系统选择器只结束这次路径选择，不确认创建。路径框可用 Enter 明确确认；输入法组合期间不触发确认。已有工程菜单中的“新建世界”进入同一新建流程。

新建时使用 core 的空白工程与保存流程。成功后才切换当前工程；失败不把未成功建立的目录当成已打开作品。需要显式 1.10–1.13 能力时，在工程内另行预览、确认并保存，不随新建自动升级。

## 打开已有作品

点击“打开工程”，输入已有作品目录或使用可选系统选择器，核对后点“打开工程”。目录默认入口是根目录 `world.wl`；兼容直接选择根目录中的 `.wl` 入口，其父目录就是工作区边界。

打开是读取已有作品的入口。空目录、缺失路径、错误入口或访问失败会显示原因并保留入口，不在原位置自动创建 `world.wl`，也不悄悄换成另一份工程。可改路径重试、返回新建，或取消。

已有工程内使用 Ctrl/Cmd+O 或工程菜单打开；新建、切换和关闭继续检查未保存工程与未应用作者输入。取消应留在原工程，不能借入口操作丢弃草稿。自动外改、冲突救援与完整备份见[工作区操作](workspace.md)。

## 命令行与源码运行

显式路径优先于最近工程，仅尝试打开指定工程。以下目录须已存在且有有效入口：

```powershell
./worldedit.exe "D:/作品/我的世界"
./worldedit.exe "D:/作品/我的世界/world.wl"
```

路径失败会进入可恢复的欢迎页并显示原因。无参数启动不要求先提供工程；参数也不是新建命令。`worldedit` 不提供远程控制运行中编辑器的 CLI，语言检查与独立演练使用 `wl`，机器会话使用 `wl-agent`，详见[CLI 覆盖表](cli-coverage.md)。

在已按[配对构建说明](paired-ci.md)检出的 worldedit 源码根目录运行：

```powershell
cargo run --locked
cargo run --locked -- "D:/作品/我的世界"
```

## Windows 图标与诊断

Windows 可执行文件使用仓库既有 `worldedit.ico` 的七种尺寸作为嵌入资源；运行窗口仍使用同源 PNG。图标含义及资产清单见[图标说明](https://github.com/ikzerok/worldedit/blob/main/assets/README.md)。仅把 ICO 放在 ZIP 旁边不足以给 EXE 本体设置图标。

Windows 的 worldedit 在普通 debug 和 release 构建中均使用 GUI 子系统，正常启动不创建终端窗口。`wl.exe` 与 `wl-agent.exe` 仍是控制台工具，其标准输出、错误与脚本用途保持。开发测试工具和测试 harness 的控制台不等同正常应用启动。

工程路径或创建错误显示在应用内，可改正后重试。窗口启动失败或 panic 会尝试写入本机诊断日志；Windows 同时显示不依赖应用渲染器的系统错误框；窗口启动失败的有界详细原因仅在本机错误框或标准错误中显示，不写入持久日志。窗口初始化返回错误或主线程未捕获 panic 时进程以非零状态退出；这不表示所有后台线程异常都必然退出整个应用。

Windows 日志优先写入 `%LOCALAPPDATA%\worldedit\diagnostics\native-errors.log`，不可写时回落到 `%TEMP%\worldedit\diagnostics\native-errors.log`。当前文件上限 64 KiB，滚动保留一份 `native-errors.previous.log`。两处均无法写入时，错误框会明确说明，不能把提示当成日志已保存。

日志仅在错误时记录 UNIX 时间、应用版本、系统/架构、进程 ID、固定错误类别，以及可用的 panic 源码文件名与行列；不记录原始错误或 panic 正文、工程路径或内容、命令行参数、环境转储或凭据。系统提示会显示实际日志位置和启动失败详情，分享截图前应检查本机用户名、路径及其他私人内容。

Linux 优先使用 `$XDG_STATE_HOME/worldedit/diagnostics`，否则为 `$HOME/.local/state/worldedit/diagnostics`；macOS 使用 `$HOME/Library/Logs/worldedit/diagnostics`。不可写时同样尝试系统临时目录下的 `worldedit/diagnostics`。非 Windows 平台将错误提示写到标准错误，不增加 Windows 式系统对话框。

## 验证与平台边界

PE 资源与子系统检查、自动交互回归、Linux 桌面和 Windows 真实桌面是不同验证层。没有实际运行 Windows 的结果时，不将资源检查或其他平台通过称为 Windows GUI 验收。当前版本已执行与未执行项目见[0.36.1 版本说明](releases/v0.36.1.md)。

浏览器版仍导入授权目录或 ZIP 快照；不能持续观察磁盘变化。Windows EXE 的图标、子系统和系统错误框不适用于 Web，浏览器保存与恢复仍遵守[工作区说明](workspace.md)。
