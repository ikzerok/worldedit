# 有界路径交换（0.29）

叙事调试器的“保存当前路径”“检查并导入路径”和“导出所选路径 JSON”使用配对
worldline runtime 的同一交换接口。编辑器不另写 JSON 解析器，不改变语言、轨迹字段、
存档格式或重放语义。规范以 `worldline/spec/replay-exchange.md` 为准。

## 录制、导出与导入

1. 显式开始试玩，按实际选择推进；在调试器为路径命名并保存。每个工作台会话最多
   保留 64 条路径，重新开始只替换 live 试玩会话，不替你写入路径文件。
2. 选中路径，点“导出所选路径 JSON”。成功后显示只读的紧凑 JSON，点“复制 JSON”
   并另存即可留存交换副本；切换选择会清空旧导出内容，须为新选择重新导出。
3. 将 JSON 粘贴进导入区，点“检查并导入路径”。只有全部检查成功才增加记录并选中
   新路径；失败保留记录、所选路径、源稿、正在试玩的状态和保存基线。
4. 成功导出的正文可重新导入，再导出得到相同的紧凑字节。导出失败会清空可交付
   JSON 区，仅在通知中说明错误，绝不会把错误文字当成 JSON，也不会修改原记录。

JSON 含完整运行状态，是作者数据。它可能包含变量、检查点和其他未作隐藏处理的
信息，与默认省略私密字段的 Markdown 试玩路径报告不同。复制、分享前应查看内容。
这项功能不增加路径数据库、工程文件、自动保存或发布权限；“保存全部”不是路径导出。

## 字节、步数与兼容边界

- 输入原始 UTF-8 字节与最终输出各最多 4 MiB，路径最多 20,000 次选择。中文按实际
  UTF-8 字节计数，JSON 转义、字段名和标点也占预算。录制与交换不再使用不同限额。
- 超限输入不进入解析与大段文本渲染。runtime 使用有界输出容器，不先生成任意大的
  JSON 再检查；合法的 1–4 MiB 路径可以交换。旧的 256 KiB 单字符串 UI 限额已移除，
  所有字符串仍受整份 JSON 的 4 MiB 总预算约束。
- 顶层和任何嵌套对象的重复键都拒绝；无效 UTF-8、非法或非有限数值、尾随内容和
  超过解析深度保护的 JSON 也拒绝，不保留部分路径。
- 当前支持 schema 1。未知可选字段仍按原 DTO 兼容策略读取；导出只含当前 DTO 已知
  字段，不保留未知字段、原始空白或原始对象键顺序。
- runtime 版本不同的合法路径仍可导入和只读查看。可读不代表可重放：开始重放仍由
  runtime 检查 schema、runtime 版本与检查点约束。入口路径可对当前编译稿观察分歧；
  检查点路径还必须匹配指纹。工具不迁移旧轨迹，也不绕过检查点验证。

失败通知保留 runtime 错误码与中文说明：`input_limit`、`output_limit`、`step_limit`、
`invalid_json`、`invalid_trace`、`unsupported_schema`。路线对照和试玩报告保留各自的
业务步数、字节与输出预算；能交换的路径不一定能完成对照或生成报告。

## 试玩快照的生命周期

普通试玩持有 runtime 的 `OwnedStory`。每次显式开始仅克隆一次对应的 Program/Analysis，
随后真实 Story 持续运行；暂停、选择、渲染与预算续行不会靠序列化/恢复检查点模拟状态。
重新开始替换旧会话，换工程或关闭释放会话。暂停、停止和运行错误仍保留当次可查看状态，
直到显式替换或关闭。源码变化只显示旧快照提示，不自动应用输入或替换正在运行的 Story。
原借用型 Story API 继续由 runtime 保留，编辑器不泄漏快照或伪造静态生命周期。

## CLI 交换副本

配对 CLI 显式提供 `wl play <入口> --trace-output <新目标.json> --trace-exchange`。
该选项使用同一紧凑交换合同，只接受一次且须同时指定输出目标；目标必须尚不存在。
编码失败不创建或截断目标，发布时原子拒绝覆盖；不支持所需文件系统操作时安全拒绝。

不加 `--trace-exchange` 时，原 `--trace-output` 的 pretty 格式、可输出超过交换限额的
轨迹、覆盖行为和退出码保持不变。普通 `replay --trace-json` 及其运行预算也不改变。
