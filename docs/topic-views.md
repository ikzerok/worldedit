# 家族、组织与历史专题视图

专题入口位于「世界关联」页。先从资料页用「查看关联」打开人物或地点，再选择家族关系、组织归属或人物 / 地点历史。

## 关系映射

每种专题分别维护自己的临时映射。为关系类型填写角色标签后，该类型 ID 才会加入本次 `Analysis::query_topic_projection` 查询；空白标签不参与查询。类型 ID、作者显示名、定义文件和行号均可见。角色不会按类型名、端点种类或旧关系自动猜测，也不会写入 `.wl` 或 Project。比如要区分生亲与养亲，需要作者把相应类型分别明确映射为「生亲」和「养亲」。

专题查询可设置一至两层、读取方向、明确对象范围、未标范围关系和子时段范围。每条关系保留原始端点、稳定关系 ID、作者标签、角色、scope、来源说明和源码位置；相同端点的多条关系不会合并。因此可分别检查多重组织归属、多个版本范围和来源不同的关系，不会由 UI 裁决其是否冲突。

宽屏关系结构图按 core 查询深度分列，节点可点击；下方列表始终提供键盘可达的对象、关系和源码入口。窄屏省略图形并保留完整列表。布局不写入共享展示配置；现有「保存共享布局」仍只保存 core 图视图命令支持的通用网络配置，不包含专题角色映射。

## 人物与地点历史

人物历史只列出正文中显式 `with` 的事件；地点历史只列出本次角色映射中 `event → place` 的语义关系。每条来源可定位到原文件行，事件、关系、时段和锚点导航使用完整 `TargetRef`（类型与 ID），同名对象不会互相替代。正文提及、反向关系和事件控制流不会被补成地点历史。

未知时间明确标为未知，不补日期。core 提供的直接 `before → after` 约束单独列出；1.9—1.12在相同直接时段/旧rank内标并列；显式1.13保留直接时段并在同一声明root/root_rank内标并列。不同root不可比，同层不表示同时，层级本身不生成全序；错误图标不完整且不提供可信层级。视图展示来源与 scope，不自行判定冲突或修补时间线。

关系环提示仅适用于当前关系页。关系页与历史页各自显示截断状态，并使用各自的 continuation；继续读取只重新查询当前分析快照，不改变语义关系或历史。
