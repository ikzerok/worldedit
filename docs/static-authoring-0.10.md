# 0.10：跨季偏序与人物资料引用

0.10 是一轮完整产品更新。作品 DSL 可显式选择 1.13；打开旧工程不会升级语言、改写清单或重新解释旧字符串。默认 1.9 及显式 1.10–1.12 的原有边界继续保留。

## 保留季节分组，表达节庆先后

当开幕属于夏季、闭幕属于初秋时，先声明一个共同的年时段，并把夏、秋和初秋放在其 `within` 层级下。作品清单明确选择 `language_version: "1.13"` 后，闭幕可写 `follows opening`，不必把两个事件都直接放到年时段。

时间线继续按事件真实的 `during` 归属显示分组。根内层级只表示显式偏序的布局：相同层级不代表同时，不同层级也不自动证明两个事件存在先后路径。可比较的根在面板中明确显示；独立时间根不会合并排序。父子关系、显示名称、源码排列和日期文字都不生成时间边。

时间顺序与读者执行顺序是两回事。倒叙依旧由原有跳转/选择决定，静态 `follows` 不执行事件、不改变 visits，也不重放状态效果。错误图明确标记不完整，不拿残缺层级冒充可信日期。事件双击返回真实声明源码；时段标题可编辑直接父级。

## 人物直接填入资料槽

如“港口指挥官”确实是一个人物值，可直接写 `property commander = ref("character", "regent")`。工程需同时选择语言 1.13，并在 required_features 声明 `content.object_refs.v1` 与 `content.character_refs.v1`。持续 schema 可以使用 `field commander_id commander ref character`；人物 ID 必须真实存在，不能以同名实体代替，也不能加 entity_type 子类限制。

资料表单的强引用选择器、模板和 schema 共用 core 的目标类型与能力门。普通字符串 `"regent"` 仍只是文字；不会通过拼写相同自动变成引用。未选新能力的作品保留旧表单能力与诊断。

使用结构重命名操作时，先核对影响预览，再明确应用。人物字段、关系端点、事件 with 与正文显式链接遵循结构身份同步；显示标签、普通正文和字符串不随意替换。取消、旧基线或外部冲突拒绝不会悄悄改写输入。删除有引用的人物必须先处理影响，不能把一个不存在的目标显示为有效人物值。

静态人物引用属性和时间资料不影响运行 fingerprint；人物自身 ID 是运行身份，改名仍可能使旧存档不兼容。此版没有动态 speaker 参数、运行时人物值、历法计算或事实/信念推理。

## 临时面板与完整工程导出

命令、搜索和偏好临时层的 Esc 逐层关闭最上层并恢复此前输入焦点；底层脏表单仍受保护。输入法组合期间不把候选取消当作工作区取消。

“导出完整世界工程”目录与工程 ZIP 使用同一范围确认。若存在未应用表单、书稿、替换预览或其他暂存输入，窗口列明种类和来源，并提供返回处理、取消以及明确继续导出已应用版。已应用但尚未保存的工程缓冲会进入副本；未应用输入不会自动应用、清空或改变保存状态。

完整副本继续保留未引用附件、未知普通文件与展示文档。普通外部冲突可把本地缓冲导出为新副本供人工合并，但不会解除原冲突或覆盖原磁盘；未解决恢复事务、越界路径、已有目标等仍遵守既有拒绝规则。导出目录/ZIP不是公开读者发布：读者包仍只包含显式白名单，没有引用闭包自动公开人物传记。

## 外部工具与兼容

工程 JSON Schema 枚举与 core 的支持集合由回归共同检查，包含 1.9、1.10、1.11、1.12、1.13，未知版本继续拒绝。core、CLI、RPC 和编辑器共用时间线投影；旧 `rank` 仍是直接时段内层级，根投影使用新增 root/order_scope/root_rank 和 complete/partial 状态。

未知语言或 required feature 的旧客户端只能按原字节保留工程，不能删除能力标记后尝试编辑。完整规范见同级 worldline 的 spec/language-1.13.md、spec/character-refs.md 和 spec/language-versions.md。
