# 从空白作品开始写作

## 产品契约

新作品仍从默认语言 1.9 的空白 `start` 事件开始。进入书稿页不会创建文件或正文；书名、章名和正文来源经作者明确确认后，才由 core 在同一事务中创建书稿编排与正式来源。没有示例句，不自动升级语言，也不自动把新事件连接到运行路线。

创建页先询问书名、章名，可选新书稿或已有书稿。正文来源必须明确选择：复用已存在的对象（空白工程可明确点选 `event:start`），或新建 1.9 空事件。稳定 ID、存放路径与事件线置于可展开高级项。创建计划优先展示书名、章名、正式来源与全部改动文件；入口及运行指纹是否变化始终可见。“运行与稳定身份”完整列出书稿和章 ID、插入位置、入口及运行指纹前后值。引用已有来源的纯编排不改运行指纹；新建事件会改变指纹，旧运行保存与检查点不能直接兼容新指纹。

“预览创建计划”不修改工程。“创建并写作”应用已经展示的计划；所有步骤成功后仅产生一次工程撤销，焦点进入第一处可写正文。正文仍只有同一正式源文件和唯一文件草稿，没有另存于章节 JSON 的副本。core 证明的空事件提供直接输入位置；UI 只传作者输入，不拼接 worldline 源码、不猜测插入范围。

## 使用步骤

1. 打开“书稿”，点击“开始写作”，输入书名和章名；已有书稿用“新建章节”续写
2. 明确选择复用已有来源或新建空白正文；需要时展开“高级：稳定身份与存放位置”
3. 预览并核对创建计划，点击“创建并写作”
4. 在正文空白处输入；“写作 / 结构 / 源码”共用同一文件草稿
5. 从已有资料导航或正文链接旁查资料，再返回原稿；“阅读预览”审阅当前未应用稿
6. 点击“应用正文草稿”，再保存工程；重开时按真实书稿和章节身份恢复

已有 Markdown 可通过空页的“导入 Markdown”进入现有导入向导。导入计划、损失确认与保存仍遵守该向导的既有边界。

## 输入与恢复

- 返回或取消创建只收起当前创建页，表单原值保留；再次进入可继续。明确“清空创建输入”才丢弃表单
- 创建计划绑定书稿与源文件基线。表单修改、工程变化或外部冲突使计划失效时，须重新预览；失败不留下孤立正文或悬空章节
- 有未应用编排或正文时先应用、恢复或保留草稿并返回，不用新事务隐式覆盖旧稿
- 输入法的启用／停用通知，以及没有活动组合时的空预编辑清理通知，不等于正在组合；普通输入或粘贴后，首次点击返回、预览或应用即可执行。真正的预编辑及提交当帧仍停用创建、应用、丢弃与返回，并保留原输入框焦点，让后续提交写回同一字段。起笔表单与正文输入框的候选键在 egui 分配焦点前处理，首次预编辑与 Tab/Escape 同帧也不转移焦点；命令、搜索、外观窗口及源文件编辑的输入继续由各自功能处理。重复点击成功的创建按钮不能创建第二份章或事件
- 正文预编辑暂存在所属输入框，包含暂时无法解析的片段时仍可接收后续提交；收到提交或明确的新输入后才调用原 core 正文接口；仅停用或转移焦点不会把预编辑当作已提交正文。临时组合与失败保留稿分别保存。冲突失败后，正文框显示当前稿，失败全文独立提供复制和明确清除；下一字符或下一次组合不能把它覆盖回新稿。相同来源的多次独立失败也分别保留。临时输入按来源身份保留并参与未应用范围提示；外变导致投影失败、当前章被移除或引用／权限变化时，即使仍有其他章节，也用独立的未完成输入框接收提交到原来源的保留稿，不覆盖当前稿。写作、结构与书稿源码三种模式遵守同样的组合代次守卫。真实组合期间从全局工具发起的导航、搜索或外观切换同样受保护；已打开上层窗口的输入不归书稿处理
- 空正文首次输入不自动应用或保存；前导空格和空行由 core 保留。无法投影时仍保留结构 / 源码救援入口
- 撤销书稿创建后，尚未应用的正文继续保留；空页的“保留的正文草稿”可查看、复制全文，并在明确确认后丢弃，不能自动覆盖新工程基线
- 请求试玩时，尚未创建的 NewEvent 正文与受保护的未插入输入会明确列为未纳入内容，须确认运行已应用稿；同名输入的正文、目标或路径变化也要求重新核对。纯引用来源与书稿排序沿用不阻挡执行的策略
- 个人外观、字号、阅读宽度、焦点与来源返回位置不写入作品内容

## 已有工作台结构

Studio 使用连续编辑平面与轻量分隔。Manuscript 把正文居中置于连续纸面，编辑工具留在纸面外。Technical 使用贴边栏头与直线工具布局。三种结构保留书稿树 / 列表 / 卡片、来源编排、资料旁阅、当前稿审阅和完整源码；改变布局不改变内容或应用边界。

参见[书稿写作与重组](manuscript-workspace.md)、[当前稿审阅](manuscript-review.md)和[工作区安全](workspace.md)。

## Focus 与 Ledger 扩展（同一 v0.30）

Studio 仍为默认，原有 Manuscript、Technical 保持可用。

Focus 使用当前有效外观（包括尚未确认的设置预览），与已有“正文专注模式”共同决定简洁布局，但不会改写个人专注开关、书稿预览开关或编辑／预览切页选择。Focus 即使在宽屏也只显示一个正文工作区；“编辑／预览”明确切换，原有阅读预览偏好不会因进入或取消 Focus 被强行打开、关闭或重置。

Focus 的书稿顶部保留“选择章节”“新建章节”“书稿管理”和“阅读预览”。专注布局将章名并入已有正文工具条，避免在正文之前重复大标题和段距；Ledger 仍由题签呈现章名。章节与分节可按已有稳定身份重新选择；书稿管理可召回完整编排操作。返回原稿、来源定位、未应用正文和输入法保护沿用原契约。原先的正文专注开关仍可与其他风格组合，不将它等同于 Focus 风格。

Ledger 用章节标题作为题签，不再在同一文面重复章名。足够宽时采用 112pt 题签、16pt 间距，至少给正文 480pt；不足时题签移至正文上方。题签只改变呈现，不改章节顺序、标题、引用、正文范围或源文件。阅读审稿也按章节保留真实标题与原有分支边界。
