# 编辑器交互架构与设计研究指南

**版本：1.0｜日期：2026-09-26｜适用项目：worldedit / worldline**\
**性质：基于官方文档的研究结论 + 待验证的设计规范草案，不是已经完成的产品改造或用户实验。**

## 0. 决策摘要与范围

本指南把“编辑器应该长什么样”转化为：作者正在处理什么对象、进行什么任务、哪些状态必须明确、哪些工具此刻应出现、如何安全结束或取消。Canvas、Hierarchy、Inspector、Timeline / Graph、Library、Command / Tool 是六种**职责**，不是六个必须同时占满屏幕的面板。正文、对照稿、运行输出也可以是主要编辑/观察区域，不应为了“像专业软件”全部放进无限画布。

主要样本为 Figma、Blender、Lightroom **Classic**、Final Cut Pro **Mac**；以 DaVinci Resolve、TouchDesigner、Unreal Editor、Notion、Logic Pro 补充反例和专门机制。Classic 与云版 Lightroom、Final Cut Pro 的 Mac 与 iPad 版本不能混为一谈。本轮以官方文档与可访问示意图为证据，没有逐一安装或操作所有商业软件；交互速度、学习成本与用户偏好均不冒充实测。Blender 部分官方页面仅取得搜索索引正文，全文抓取受限，见来源台账。

旧视觉路线允许全部推翻。此前石墨灰/青绿配色、12 页面分组、880 逻辑点阅读列以及提交 `357b1a1` 都只是历史实验，不是本方案的设计约束。旧 UX 票应记录为“被替代 / 不再按原范围实施”，而非“已实现”。CAP 同类产品能力路线独立保留，不能因调整 UI 而关闭能力票。

**建议的首轮方向：稳定的工作台外壳 + 少量任务预设 + 共享对象上下文 + 可恢复的面板；先不做完全自由拼装的 Blender 式桌面。** 这是候选方案 B，必须与“固定三栏”和“完全自由布局”做任务原型比较，不把本建议当作已经通过用户验证的结论。

研究与交付链必须可追踪：`SRC 来源 → OBS 观察 → PAT 模式 → DEC 设计决定 → EDS 工单 → TEST 验收`。每条规则须说明适用条件和不适用情况，不能只写“简洁、现代、高级”。

## 1. 从样本中学习什么

### 1.1 Figma：同一对象，不同投影，同一个操作目标

**官方可确认。** Figma 把画布、层级/资源入口、选择相关属性和创建工具分工；选中图层后，右侧显示相应属性，权限影响能否修改；个人缩放只影响自己的视图。层级选择与画布选择可用于定位对象。[S01–S02]

**机制解释。** 值得学习的不是右侧栏的颜色，而是“我选中了谁”成为跨区域共享的上下文。画布负责空间操作，层级负责结构定位，检查器负责精确修改，三者不能各说各话。属性随选择变化，但面板位置与字段组织应尽量稳定。

**必须研究的场景。** 从画布选中嵌套对象；从层级找到被遮挡对象；同类与异类多选；锁定对象；无选择；在输入框编辑时切换选择；浏览工具与变换工具切换。记录每一步的 selection、focus、属性作用域、可用命令及恢复路径，不只记录最终截图。

**迁移到本项目。** 地图标记选择应同步显示所属地图/图层和关联 `TargetRef`，但“标记外观”与“关联资料正文”属于不同对象，检查器必须显示当前修改哪一个。库里的资料可以被多个地图入口引用，不能把重复出现的入口当成多个实体。

**不照搬。** 不复制品牌图标或固定像素布局；不把云端实时保存模型硬套到本地文件；不以所有对象都有 x/y 为由把叙事资料变成空间对象；多选批量修改在 core 未支持前不得只在 UI 拼接实现。

### 1.2 Blender：编辑器是可组合的工作环境，而不是业务页面集合

**官方可确认。** Workspace 由多个 Area/Editor 组成，面向任务组织；Area 可调整、拆分并临时最大化。Properties 可显示数据上下文路径并固定到特定对象，避免后续选择覆盖它。Blender 的部分快捷键按鼠标所在编辑区解释；其工作区还可随 `.blend` 保存与加载。[S03–S05]

**机制解释。** “在哪种工作环境中做事”“哪个编辑区有焦点”“哪个数据对象正在被检查”必须分离。全屏某一区域是临时专注，不等于销毁其他区域；固定检查对象是一种阅读/比较需要，不应破坏主编辑选择。

**必须研究的场景。** 切换任务工作区后回来；最大化后恢复；固定检查器后选另一对象；把第二个编辑区切换为另一种观察方式；布局缩窄或屏幕移除；键盘指令在不同编辑区的作用。拆分手势的可发现性和错误恢复要作为风险记录。

**迁移到本项目。** 允许“写作、世界组织、逻辑调试、审阅”使用不同组合，而不是新增几十个同级标签。先做预设、有限分区与重置；多资料钉住由 CAP-02C 提供能力，工作台设计只规定其呈现和选择规则。

**不照搬。** 不默认支持任意分割、任意多窗和按鼠标悬停路由全部快捷键。中文输入场景优先按真实键盘焦点分派。Blender 随工程保存布局是它的契约，不是本项目默认策略：个人布局默认不能污染作品文件。

### 1.3 Lightroom Classic：参数操作始终围绕可比较的结果

**官方可确认。** Classic 用 Library、Develop 等模块区分工作阶段；Develop 将预设、历史等与调整参数分区，并提供 Before/After 对照。面板可折叠，Solo mode 可让一个面板组只展开一项；面板可隐藏或恢复。[S06–S07]

**机制解释。** 参数编辑应形成“选对象 → 调参数 → 看结果 → 比较 → 保留/回退”的短循环。频繁参数和高级参数可渐进展开，但用户应知道哪些值已改变、重置的范围是什么。减少视觉噪声不能牺牲修改范围的可见性。

**必须研究的场景。** 数值拖动与精确输入；临时禁用一组效果；恢复默认；比较原始/当前；复制部分参数到其他对象；长面板的滚动与单组展开。尤其要观察批量同步的范围提示，而不把快捷批量操作一律评价为优点。

**迁移到本项目。** 地图样式与布局可用受限即时预览；资料/关系表单使用草稿与明确应用；审稿以 base/current/proposed 解释变更。常用字段在前，高级栏目按需展开；改变字段不能导致焦点跳转或整个检查器重排。

**不照搬。** 自然语言正文不是滑杆参数；默认值、空值、继承值与未知值必须分开。高风险内容编辑不能仅因“即时反馈”就自动写文件。图像的可逆参数处理也不能证明本项目具有持久版本历史。

### 1.4 Final Cut Pro：素材、使用实例、编排和观察位置各有身份

**官方可确认。** FCP 的 browser、viewer、timeline、sidebar、inspector 可以按任务调整或隐藏；timeline index 为图形编排提供文字索引。skimmer 和 playhead 是不同位置状态。Magnetic Timeline 中插入、修剪和移动会影响邻近片段的位置。[S08–S11]

**机制解释。** 素材库回答“能使用什么”，时间线回答“如何编排这些使用实例”，查看器回答“结果是什么”。临时扫看和实际执行位置不应混同。非文字图形必须提供可搜索、可定位的文字后备。

**必须研究的场景。** 浏览素材但不改变播放位置；从编排实例找回源素材；点击索引定位；范围选择与片段选择；移动片段前后的受影响区域；隐藏检查器后保持精剪工作；不同工作区保持同一作品上下文。

**迁移到本项目。** 书稿章节顺序、世界事件偏序、可执行控制流分别呈现、分别命名。选中某事件不自动推进演练。图中事件可从列表进入，返回时保留筛选、展开层级和镜头。书稿编排将来引用既有正文，避免复制真源。

**不照搬。** 磁性吸附是剪辑语义而非装饰；不能为排布整齐自动改变历史先后、剧情出口或关系。没有精确时间/时长的对象不得伪装为按比例时间轴上的片段。

### 1.5 五个补充样本：只借鉴机制，不扩张本项目领域

| 样本 | 可确认的设计机制 | 提取的知识与本项目边界 |
|---|---|---|
| DaVinci Resolve | 以专门 page 分配剪辑、特效、调色、声音及交付工具。[S12] | 任务阶段可以组织工具，但作者不必按固定流水线顺序工作；同一对象跨工作区不产生副本。不为了对标增加调色/音频模块。 |
| TouchDesigner | 网络路径与返回、节点内预览、Viewer Active 区分节点移动和预览操作；网络还可用列表模式。[S13–S14] | 节点容器和内部内容必须有明确命中区与模式；世界语义关系不是实时数据流，不借用流动连线暗示因果或运行。 |
| Unreal Editor | Viewport、Outliner、Details 协同；Content Drawer 临时打开，亦可固定为常驻浏览器；Details 可锁定对象。[S15] | Library 可按需调出，不必永远占屏；必须区分资产与场景实例。别把世界资料库变成“所有东西必须放进场景”。 |
| Notion | 选文出现格式操作、斜杠命令、块操作入口；数据库条目可侧览、居中或整页打开。[S16–S17] | 工具靠近意图发生处；阅读、短暂旁查、持续编辑是不同打开方式。“GUI 消失”不等于只剩不可发现的 hover 控件。 |
| Logic Pro | Smart Controls 汇集选中轨道的重要参数，部分控制可映射多个底层参数。[S18] | 可为资料提供“常用操作”，但多字段联动必须可解释并受事务保护；不把未建模的操作伪装为宏。 |

这些样本没有共同证明某一固定布局“最优”。它们提供相互制约的方案：Figma 的稳定区域与 Blender 的可重构布局、Notion 的就地工具与专业编辑器的常驻控制，都应根据任务而非名气选择。

## 2. 研究单元、证据分级与来源管理

### 2.1 最小研究单元不是截图，而是一次完整任务片段

统一记录 `任务/对象/前置状态 → 用户动作 → 界面变化 → 数据变化 → 完成/取消/失败恢复`。截图只证明某时刻的视觉结构，不能单独证明快捷键、自动保存、撤销粒度、延迟或学习成本。

每个主要样本至少选择 4 个与本项目可比的任务族，任务中至少覆盖进入、选中、修改、确认、取消和恢复。建议形成 16 条主要成功路径及对应负例；这是研究配额，不是本轮已完成数量。领域不适用的任务标 N/A 并写理由，例如不要求 Lightroom 提供世界关系图。

### 2.2 证据标签

| 标签 | 含义 | 可以支持的结论 | 不能支持的结论 |
|---|---|---|---|
| DOC | 官方手册/帮助的明确说明 | 被描述的功能与操作规则 | 本机实测性能、用户更喜欢它 |
| IMG | 实际查看过的官方或自有截图/录屏帧 | 布局、层级、选中/提示的可见形式 | 帧间行为、撤销语义、付费能力可用性 |
| RUN | 研究人员可复现操作记录 | 该版本、平台、输入下的行为 | 全部版本/平台都一致 |
| USER | 目标用户任务测试 | 该样本的成功、错误、理解和偏好 | 小样本统计推广到全部人群 |
| HYP | 基于证据的机制解释/假设 | 原型与实验问题 | 已验证的因果关系 |
| DEC | 经过批准的项目设计决定 | 约束后续设计和实现 | 竞品同样这样做或已开发完成 |

本轮主要为 DOC；已查看 Figma 官方区域示意与 FCP 窗口图。未取得的原图、未登录功能、未执行路径全部留空，不能补造。观察员必须保留事实、解释、建议、验证结果四个独立字段。

### 2.3 每条观察必须提取的信息

| 字段组 | 必填信息 |
|---|---|
| 来源身份 | source_id、URL、标题、访问日、产品/版本/平台、已知权限或套餐；未知则写 unknown |
| 任务 | 用户角色、熟练度、目标、任务频率、风险、前置文件和对象、成功终点 |
| 对象模型 | 真源/实例/容器/引用/投影；唯一身份；层级是文件、包含、语义还是顺序 |
| 界面状态 | 主编辑区、selection、active target、hover、keyboard focus、inspector pin、工具/模式 |
| 空间 | 逻辑窗口尺寸、DPI/缩放、区域边界、可滚动范围、遮挡、主内容可用比例 |
| 动作 | 输入方式、命令名称、触发器、目标解析、前置条件、禁用原因 |
| 结果 | 即时反馈、预览/缓冲/磁盘写入、受影响范围、撤销/重做、完成与失败路径 |
| 成本 | 寻找动作的时间、离开主任务的次数、面板切换、误操作、恢复时间；没有计时就不填数字 |
| 迁移判断 | 本项目使用场景、收益假设、代价、反例、替代方案、下一项验证 |

跨版本截图不可直接测量像素对比；不同设备先换算为逻辑尺寸。自动隐藏、弹窗等行为至少记录前后帧和触发条件。记录鼠标路径时区分主动操作、等待和研究员讲解，避免混成“完成用时”。

### 2.4 八个研究维度

**目标与心智模型**：作者如何解释对象和关系；新手第一次在哪里开始。**对象与信息结构**：原件、实例、引用、集合、属性如何区分。**任务与导航**：跨上下文如何返回，工作区是否改变任务内容。**选择与状态**：选中、焦点、预览、编辑对象是否一致。**命令与反馈**：触发、作用域、可发现性、撤销及错误恢复。**空间与显隐**：何时占屏、如何折叠、谁优先。**视觉与阅读**：文字、密度、色彩语义、控件层级。**技术与可达性**：键盘、IME、辅助技术、平台、性能、大数据退化。

优先研究前六项，最后再定配色和圆角；但可读性、错误可见性不能拖到收尾才检查。

## 3. 六种职责的设计契约

本节中“必须”是拟定的产品安全/一致性约束，“应”是有反例时可以偏离的默认，“可”是可选能力。规范批准和实现完成分别记录。

| 职责 | 必须回答的问题 | 应出现的时机 | 可退场的时机 | 恢复入口与不可破坏的内容 |
|---|---|---|---|---|
| Canvas / 主编辑区 | 我正在编辑或观察什么？这是原文还是投影？ | 每个任务必须有一个明确主区域 | 只有显式切任务、打开主文档或比较模式才替换 | 标签/标题/面包屑；保留文本光标或镜头，不能因 hover 换稿 |
| Hierarchy / 导航结构 | 对象在哪里，属于什么组织关系？ | 找对象、批量组织、理解层级时 | 连续写作/细调/专注时可折叠 | 搜索与结构按钮；必须标明树的语义，文件目录不是世界隶属 |
| Inspector / 检查器 | 当前修改谁的哪些属性，改动是否已应用？ | 选择可检查对象或打开属性命令时 | 无选择且无固定对象/未提交输入时可收起 | 对象标题与固定标记；不得静默关闭含草稿的检查器 |
| Timeline / Graph | 是时间偏序、阅读次序、控制流还是语义关联？ | 任务需要时成为主区域或辅助投影 | 普通写作、参数编辑、阅读时可隐藏 | 清晰视图名和索引；隐藏不删边、不推进故事 |
| Library / 资料资源库 | 我还能引用、放置或导入什么？ | 创建、引用、查找、选择素材时按需打开 | 完成一次插入且无未提交输入时可退场 | 常驻按钮/命令；浏览不自动插入，固定后不随焦点消失 |
| Command / Tool | 现在能做什么，作用于谁，怎样取消？ | 全局命令有稳定入口，局部工具靠近主任务 | 不相关工具可隐藏；有意义但暂不可用者说明原因 | 命令搜索、菜单、可见取消；危险动作不得只靠 hover 找到 |

**另有横向约束：状态与恢复。** 保存状态、只读/冲突、活动操作、运行版本、撤销与关闭保护必须跨六类区域一致。它们不是必须再增加的第七个大面板，而是不能随简化界面消失的产品承诺。

### 3.1 显隐不是“自动猜测”，而是可解释状态表

`PanelPolicy = f(task, view, selection, pin, edit_session, capability, focus, available_space)`。首版使用确定性规则，不用用户无法预测的频率排序或自动布局猜测。

| 状态/事件 | 行为规则 |
|---|---|
| 无选择 + 无固定检查对象 + 无草稿 | 检查器收起或提供小型上下文说明，不留满高空表单 |
| 选择对象 A | 跟随式检查器显示 A；层级可 reveal A，但不默认重排树或强制改变镜头 |
| 检查器固定到 B 后选择 A | 检查器继续显示 B，并醒目标注“已固定：B”；编辑命令使用明确 owner，不能猜 A/B |
| A 的表单未提交，又想选择 B | 保留 A 的草稿或明确询问应用/保留/放弃/取消；基线失效不能靠确认绕过 |
| 临时资源抽屉失焦 | 只有无拖放、无输入、无弹出子菜单/模态操作时才允许退场；不能把刚选素材误插入 |
| 进入专注模式 | 保存原面板/焦点状态；只隐藏非必要区域，保留可见退出入口、必要的冲突提醒 |
| 缩窄窗口 | 优先保主编辑区，辅助面板转抽屉/标签；不丢选中对象、输入或面板固定状态 |
| 切换工程 | 结束/保存/保留旧稿由明确流程决定；不得将上一工程 TargetRef 套到新工程同名对象 |
| 只读/未知能力 | 可检查但不能伪装可写；显示原因与恢复入口，隐藏修改工具不等于隐瞒错误 |
| 恢复默认布局 | 只重置个人布局，不恢复工程内容；操作有清楚名称且不清理文稿 |

面板应在稳定边界内切换内容，而不是每次选择都左右跳动。用户固定的区域优先于一般自动折叠；若尺寸不足，转为可恢复标签，不允许完全挤走主区域。

## 4. 先统一状态和对象，再画布局

### 4.1 必须分开的六个“当前”

`hover_target` 是鼠标短暂停留；`selection` 是选中的对象集合；`active_target` 是集合中当前主要对象；`keyboard_focus` 是输入接收者；`inspected_target` 可以跟随或固定；`preview_cursor` / `runtime_position` 是观察与运行位置。它们可以关联，但不能用一个全局 selected 字段互相覆盖。

建议定义带类型的 UI 标识，而非仅存字符串：`TargetRef`、`MapPlacementRef(map_id, placement_id)`、`GraphEdgeRef`、`SourceRange(file, baseline, range)`、未来 `ManuscriptItemRef`。任何跨视图跳转返回携带身份、来源、镜头/滚动和原焦点。旧表单的来源基线也随编辑会话保留。

一个对象有多个投影不等于多个真源。选中地图入口先得到标记身份；要改关联实体，必须明确打开实体属性；“隐藏此边”“删除展示入口”“删除资料”“删除语义关系”是不同命令，文案、确认范围、撤销结果都不同。

### 4.2 状态所属域

| 域 | 例子 | 保存/撤销原则 |
|---|---|---|
| 临时交互 | hover、菜单、拖动中间点 | 不写工程，不作为独立内容撤销 |
| 个人会话 | 镜头、导航历史、当前选择、临时面板 | 默认为本次会话；不改变内容指纹 |
| 个人持久偏好 | 工作台布局、文字缩放、快捷键 | 独立本机存储；失败退回默认，不虚报作品保存 |
| 编辑草稿 | 未应用正文、属性输入、连线意图 | 保留原值与基线；取消不修改 Project；失效不能覆盖 |
| 作者共享内容/展示 | 实体、关系、显式共享布局/预设 | 走 core 命令、候选校验、撤销、可恢复保存；两种分域不能混同 |
| 运行/调试 | 演练位置、状态、重放路径 | 与作者文档分开；显示程序版本，检查不推进执行 |

研究 UI 模式时必须记录写入属于哪一域。界面即时更新不等于保存成功，应用到缓冲不等于磁盘已写，浏览器下载已发起不等于用户已落盘。

### 4.3 正交状态，不做模式笛卡尔积菜单

工作台预设、主要投影、编辑模式、当前工具、运行状态、保存/冲突状态是不同轴。例如：世界组织 / 地图 / 编辑展示 / 多边形工具 / 未演练 / 有未保存修改。顶部无需列出每种组合，但活动模式、对象 owner 和未结束动作必须可见。

`Idle → Previewing → Validating → AppliedToBuffer → Saved` 是编辑路径；`Cancelled`、`RejectedStale`、`ReadOnly`、`Conflict` 是明确出口。pointer_move 只更新预览，pointer_up 才尝试一次提交；Escape 返回操作前状态。验证失败保留可修复输入，不只弹一个随后消失的 toast。

### 4.4 命令与撤销

命令统一描述：`id / label / owner / allowed_contexts / arguments / enabled_reason / preview / commit / undo / persistence_domain`。菜单、快捷键、右键和按钮调用同一命令，不实现四套规则。

路由优先级建议：模态操作 → IME/文本控件 → 有焦点编辑区 → 全局安全命令。Delete 在文本框删除文字，不能同时删除图节点；组合输入过程中单键快捷键不能建节点。Escape 先取消最内层操作，再退出临时模式；有草稿时不得静默关窗。内容撤销、文本尚未应用的本地编辑撤销、布局重置应有明确 owner，不能碰巧落到最后点击的窗格。

## 5. worldedit 候选工作台与既有能力映射

### 5.1 三个方案都要比较

| 方案 | 潜在收益 | 主要风险 | 首轮研究处理 |
|---|---|---|---|
| A 固定三栏，按页切换 | 规则少、实现可控 | 写作/审阅/图形任务争抢空间，容易继续增加页面 | 保留为低成本比较基线 |
| B 稳定外壳 + 任务预设 + 有限分区 | 同时兼顾稳定性、任务适配与返回 | 必须定义跨区域上下文、草稿和焦点 | 首选原型，不是已批准最终方案 |
| C 任意 dock / split / 多窗口 | 专家可深度定制 | 学习、焦点、布局恢复、Web 与多 DPI 成本高 | 首轮只做边界原型；未经证据不实施完整系统 |

评价先过安全门，再比较任务成功、恢复、查找成本、上下文切换、阅读/画布可用空间、键盘可达和实现成本。不能用外观评分抵消丢稿、误改对象或越权写入；不得编造带小数的“综合评分”冒充测量。

### 5.2 候选任务预设

| 预设 | 主区域 | 导航结构 | 检查器 | 时间/图 | 资源库与命令 |
|---|---|---|---|---|---|
| 写作 | 当前正文与段落编辑 | 大纲/资料检索，可折叠 | 默认按需；旁查可固定 | 默认隐藏，需要时侧览 | @/就地引用与新建；书稿能力尚由 CAP 提供 |
| 世界组织 | 地图、关系图或资料列表三种投影 | 项目集合/图层，明确当前树语义 | 跟随选中，区分标记与内容 | 当前主投影或辅助历史列表 | 资源抽屉、创建/关联、显式保存共享展示 |
| 逻辑与演练 | 控制流图和演练输出 | 事件/诊断索引 | 条件与状态解释 | 世界时间只按需查看 | 运行/停止/定位；重放依赖 CAP 能力，原型可用标明的假数据 |
| 审阅 | 差异/讨论或只读原稿 | 变更与冲突队列 | 引用影响与上下文 | 只在解释关系时出现 | 采纳/拒绝/重新比较；对外发布属于独立有确认的流程 |

预设名和数量都是待验证假设，不要求作者先“收集→编排→演练”按步骤通关。少量任务预设不能消灭快速检索和任意返回。发布是有风险的独立命令流程，暂不强制设置第五个常驻工作区。

### 5.3 12 个旧页面不等于 12 个必须保留的菜单

正文概览可成为阅读投影；时间线成为世界偏序投影；事件关系图成为控制流投影；世界关联成为语义关联投影；地图成为展示投影；人物/世界观/资料与状态/Wiki 可成为不同实体入口或库筛选；协作审阅成为任务工作台；源文件成为专家后备；试玩成为运行观察区。**迁移必须逐项证明旧能力仍可到达，但无需继承原有页面外壳。**

当前代码已有分散的 `reading_target`、`catalog_target`、`network_selected`、`map_selection` 与地图未提交保护。研究应审计这些状态的 owner 和转换，而不是先机械合成一个全局变量。参照 `src/app.rs`、`src/app/reading.rs`、`src/app/maps.rs`、`src/app/network.rs`、`src/app/authoring_forms.rs`；结构写入仍唯一由 core 承担。

### 5.4 四条必须画完整的原型路径

**路径 A：写作旁查。** 正文选中文字 → 调出资料候选 → 同名消歧 → 临时侧览 → 固定旁查 → 返回原光标继续输入。期间主文稿不被替换，搜索框焦点不误触主文稿快捷键；新建能力暂未实现时明确显示原型状态。

**路径 B：编辑地图入口。** 浏览地图 → 选中入口 → 显示标记 owner/关联实体 → 显式进入编辑展示 → 拖动预览 → Escape 取消 → 再拖动并提交 → 一次撤销。打开实体正文不得把标记坐标变成实体地理事实。

**路径 C：理解事件。** 在资料列表选择事件 → 查看世界时间偏序 → 切控制流 → 临时预览原文 → 回到图 → 开始/停止演练。事件时间、控制流、选中位置和运行位置分别标识，切图不重走剧情。

**路径 D：审阅过期修改。** 打开提案 → 查看三方差异 → 另一来源更新 → 旧预览标失效 → 保留解决草稿并重新比较 → 验证后采纳或取消。没有同字段默认赢家，输入不因面板关闭被丢弃。

### 6.1 知识必须同时记录代价

一张合格模式卡必须有：背景、用户问题、证据、触发条件、结构、状态转换、数据域、副作用、取消/恢复、键盘替代、适用规模、反例、替代方案和验证结果。没有边界的“隐藏面板更简洁”不是可复用知识。

例：固定检查器减少重复打开资料的成本，但引入“眼前选中 A，实际编辑 B”的风险。补救不能只是一个很小的图钉，而应在标题显示 B、提供解除固定与定位 B 的入口，并在提交摘要中再次标明 B。是否值得固定由旁查任务的错误率和恢复成本验证。

## 7. 视觉规范要服务状态，而不是替代架构

先做无品牌中性色结构原型，再决定主题。深色不是专业性的证明；浅色/深色和紧凑/舒适至少作为可比较状态，不要求首期全部生产化。沿用旧主题也必须重新给出任务和可读性依据。

设计 token 分为：`surface`（主内容/工具/浮层）、`text`（正文/辅助/禁用）、`state`（选中/焦点/预览/错误/警告/修改）、`edge`（关系类别）、`spacing`、`type`、`motion`、`hit_target`。每个 token 同时说明用途与禁止混用范围。活动工具、选中对象、键盘焦点和未保存不能都画成同一种绿色。

组件规范必须覆盖 default、hover、focus、selected、disabled、read-only、dirty、preview、error、loading、empty、conflict。没有状态矩阵的组件截图不算设计完成。文案需要说明“应用到缓冲”“保存到文件”“导出备份”“发布给读者”的区别。

尺寸只给原型起点，待验证后定稿：侧区建议先试 240–320 逻辑点，检查器 280–360；正文以可读行宽验证而非固定 880；常用命中区先试 32–36，图标视觉尺寸与命中区分开。遇到窄窗先改变区域组织，不一味缩字。上述数值不是从竞品截图量出的行业标准。

普通文字可参考 WCAG 4.5:1，Web 指针目标至少 24×24 CSS px 或满足相应例外；还须检查焦点不被作者内容遮挡及拖动的单指针替代操作。[S19–S22] 本项目可采用更严格的完全可见焦点策略；原生逻辑点不能直接当 CSS px，满足配色断言不代表完整无障碍符合性。

拖动重排、连线、平移等动作应有键盘或菜单等价路径；中文 IME、复制长文、错误后保留输入、可访问名称/角色/状态都要测试。不要用手绘文字取代有语义的按钮而不提供可访问性信息。

## 8. 怎样决定采用、修改或拒绝一个方案

### 8.1 设计决定卡

每个重要选择记录：问题、目标任务、证据 ID、A/B/C 方案、约束、收益假设、风险、决定、拒绝理由、验证方法、回退条件、关联工单。由谁批准、何时批准单独填写；本轮未指定审批人。

**示例 DEC-01（建议，未批准）**：首版采用有限任务预设，不做任意 dock。依据：本项目需支持长文、图形和审阅；DOC 证据说明预设和临时展开可表达这些工作环境，但没有 USER 证据证明作者愿意学习复杂分屏。下一步用同一雾港工程比较 A/B/C；若 B 引入更多误改或找不到工具，回退 A 并保留只读侧览。

**硬性否决条件**：不明确编辑 owner；隐藏唯一恢复入口；非显式动作改内容；为了布局推断语义；取消丢稿；只读状态仍可写；图形信息无后备可达；将研究图/假数据当运行或功能证据。

### 8.2 研究成果怎样变成 ticket

研究票交付证据与结论；设计票交付契约与候选原型；原型票交付可运行实验与已知限制；实施票才交付生产代码；验证票负责判定目标是否达成。一个“改漂亮”的大票不能同时承担所有角色。

每票必须包含用户任务、已有能力/缺口、来源及 PAT/DEC、明确非目标、状态矩阵、数据域、风险、可复现验收、依赖和回退。设计票不得以 65 项旧验收或 108 项旧测试作为新方案完成证据。

## 9. 验证计划与推进门

| 门 | 进入下一步前必须具备 | 未通过时怎么办 |
|---|---|---|
| G0 研究与边界 | 主样本官方资料、关键 DOC/IMG 观察、缺失 RUN 明示；作者任务和对象关系图 | 补证据，不立即选颜色或重写页面 |
| G1 状态与语义 | selection/focus/pin/preview/owner 契约，显隐矩阵，命令与数据域表 | 先修状态冲突，不用动画掩盖 |
| G2 低保真对比 | A/B/C 在同一任务下的可操作原型；成功、取消、错误与窄屏路径 | 拒绝不合适布局，保留低成本基线 |
| G3 设计系统 | 组件状态、排版/密度、可访问性规则与主题语义；关键高保真状态 | 回到相应模式/决定卡 |
| G4 技术原型 | egui 最小真实流程、焦点/IME/面板恢复/草稿保护；未实现 CAP 使用显式假数据 | 缩小布局能力，不重写 core 语义 |
| G5 用户与回归 | 新方案目标用户任务记录、原生/Web 交互、性能与现有功能可达映射 | 记录失败和回退，不能只放成功截图 |
| G6 渐进合入 | 审批后的实施拆票、精确配对 SHA、功能开关/回退、迁移文档 | 旧方案继续可用，不覆盖既有 release/tag |

### 9.1 任务测试方法

建议先做 6–8 位目标作者的小样本形成性测试，区分首次使用者与熟悉项目者；这不是统计显著性保证，亦不宣称已经招募。每人执行写作旁查、地图入口修改、事件跨投影理解、审阅过期修改、找回隐藏面板、键盘完成关键操作。A/B 顺序交叉，任务等价但内容不同，避免学习效应完全偏向后测方案。

记录成功/部分成功/失败，误改对象次数、找不到命令次数、恢复次数、耗时分段、主观难度与解释原话。操作时间与“为什么这样设计”的主观偏好分开。采用方案前先定指标，不看结果后临时改阈值。效率提升目标在取得基线后批准；本轮不编造百分比收益。

### 9.2 工程验证矩阵

桌面/Web 分别测试 1024×640、1280×800、1440×900 等**逻辑尺寸起点**与系统/浏览器放大；按设备能力覆盖 100%、150%、175%、200% 并记录实际有效比例。不是把截图缩小后宣称已测 DPI。主编辑区、取消、保存、面板恢复、错误文本始终可达；浏览器不显示无效的操作系统窗口控制承诺。

数据涵盖：空工程、同名实体、长 ID、长篇中文/emoji/混合文本、深层结构、多重引用、250 节点/500 边的受限图、总数据 1000 对象/3000 关系、损坏文件、未知能力、只读、外部冲突、陈旧表单。大图裁剪或分页必须显示局部性，不伪装全图。

自动断言包括：浏览/布局/临时预览不改 Project；确认只作用于声明 owner；一次拖动一次撤销；取消零写；切工程不串目标；不丢草稿；命令跨入口等价；所有旧能力可达。UI 事件测试、截图、用户理解和性能是不同证据，不互相替代。

性能分冷启动、暖态交互、输入到反馈、布局/绘制和后台分析计时。记录硬件、OS、编译模式、DPI、数据、样本、P50/P95/最差和内存峰值；保留相同夹具的基线。历史 11.073 ms / 4.128 ms 只用于定位旧记录，不能给新方案背书。测试标准未批准前不自动生成“PASS”。

### 9.3 发布与知识治理

研究指南和观察索引纳入 Git；只存必要小体积图片或外链及校验，不上传字体、用户私密项目或整个工具截图库。未获许可的商用素材不复制进产品。每条知识有 reviewed_at、supersedes、验证级别、版本适用性；重要软件更新或任务改变时重新核验，而非定时盲抓全部页面。

本轮创建新的 EDS 路线，旧 UX-MAP / UX-01—06 以“被替代”关闭并保留历史。CAP-MAP 与能力子票仍独立；EDS 可以规定能力如何呈现，但不能把尚未实现的书稿、模板、重放或读者发布算作 UI 已实现。新代码的合并与发行须另经实施和验收，不由研究文档上传隐式触发。
