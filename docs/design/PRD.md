# worldedit 产品需求文档（PRD）

**版本：0.2 / 待评审（0.2修订：M1矢量画布，栅格图层化，预算指向契约阈值登记）**\
**日期：2026-09-19**\
**代码基线：`b0955adcccd740d9b3b46cee1d0f503ad25f5257`（工具0.2.0）**\
**产品定位：共同编写世界内容，并以资料、地图、关系网络和故事多视图呈现的作者工作台。**

本PRD与[架构文档](ARCHITECTURE.md)、[共同契约](https://github.com/ikzerok/worldline/blob/cf4cdeac3ed56fb62bf840d5adfc2047d0d5d912/spec/presentation.md)、[需求清单](https://github.com/ikzerok/worldline/blob/cf4cdeac3ed56fb62bf840d5adfc2047d0d5d912/docs/design/shared/REQUIREMENTS.md)配套。新增能力是设计目标，不是已上线功能；R/E来源见[研究记录](https://github.com/ikzerok/worldline/blob/cf4cdeac3ed56fb62bf840d5adfc2047d0d5d912/docs/design/shared/RESEARCH.md)。

## 1. 产品问题与目标

当前工作台已有时间线、剧情关系图、人物、资料与状态、Wiki、世界观、源码和试玩等入口；共享快照驱动主要视图。[R07] 新版不推翻这些能力，而是增加一个可自然阅读世界的地图入口，以及跨类型关系网络。

作者不应为显示一个地点而写运行逻辑；读者不应为了查某组织而启动故事；多人合作不应因一个人缩放地图而改动其他人的镜头。

**成功体验：打开雾港地图→点击灯塔→阅读同一份资料→查看维护组织与人物→进入相关历史和故事→返回原地图。整个阅读过程不改设定。**

## 2. 用户与主要工作

| 场景 | 使用需求 |
|---|---|
| 作者快速记录 | 从名称与自由正文开始，不被大量必填栏目打断 |
| 地图整理 | 上传已有底图，把内容入口、路径和区域摆在合适位置 |
| 关系梳理 | 查看明确联系，补写关系说明，不面对一张无法阅读的全世界大图 |
| 多人分工 | 对内容和地图分别讨论，知道哪个修改来自何处 |
| 故事组织 | 关联人物、世界事件、章节和锚点，保留现有分支创作 |

不预设所有用户都是程序员；新内容、标记和关系的日常操作需要有表单和搜索，源码是并行入口而非强制步骤。

## 3. 范围

### 纳入

二维底图浏览、点线面标注、图层、子地图、资料跳转、局部关系网、可选内容模板、反向引用、作者专题视图、内容/展示修改保护、批注与提案、原有故事能力的无回归保留。

### 排除

任何世界自动或半自动演化、游戏式资源计算、人物自动行动、模拟世界时钟、实时位置驱动地图、自动历史生成。不做酒馆卡或上下文，不以三维引擎、完整地图绘制/GIS、在线瓦片服务和实时云协作为本期前置。

自动聚合标记、搜索索引、关系布局可以采用，但只改变显示和检索结果。

## 4. 信息架构与入口

建议在现有导航中新增“地图”和“世界关联”，保留“事件关系图”并解释其为剧情执行图。内容库逐步统一人物/世界/词条入口，不在M1一次性搬动所有旧界面。

```text
世界工作台
  内容：人物、地点、组织、物品、文化等
  地图：地图列表 / 地图画布 / 图层 / 标记
  世界关联：局部网络 / 关系详情 / 专题
  故事：正文、历史、时间线、分支、锚点
  工程：源码、诊断、保存、协作修订
```

地图界面文字布局：左侧地图与图层，中间画布，右侧统一资料/标记检查器，顶部搜索、浏览/编辑展示切换，底部图例与错误摘要。窄窗口允许折叠侧栏，不遮挡核心画布。

## 5. 地图需求

### 5.1 创建与栅格图层（WE-001/002）

进入地图空白态，选择“新建地图”：地图文档自带逻辑坐标系与extent（首次导入位图时默认取其像素尺寸），从工程素材选择PNG/JPEG作为栅格图层放置进该坐标系，或通过明确导入复制到工作区。导入前显示尺寸、预计解码开销和支持范围。取消不能留下半个注册项。

地图画布为矢量原生：标记、折线、多边形是原生图元，栅格图像只是可放置、可替换的图层；更换或移除栅格图层不移动任何已保存图元。外部SVG等矢量文件导入不是本期目标。允许暂时没有栅格图层的空白画布；缺失图层素材以占位显示并保留图元。首版不承诺任意大图；超出预算（见共同契约阈值登记）给出具体原因，不默默压缩替换原图。

### 5.2 浏览（WE-003/014/026）

支持拖动画布、指针中心缩放、适配视口、重置、名称搜索及键盘操作。标记图标/名称可通过列表访问，不能仅靠颜色或精细鼠标点击。

点击对象标记打开统一资料侧栏；同名对象显示kind及ID后缀进行消歧。返回恢复原镜头和选中项。只浏览、图层临时开关、搜索和跳转不会点亮“共享修改未保存”。

### 5.3 标记与编辑展示（WE-004/005/006）

默认浏览模式。进入“编辑展示”后方可创建或拖动标记；选择已有对象或建立说明标记。作者需能注明人物标记的用途，如出生地、故居、某章所在地，不显示为系统推测的“当前所在”。

拖动只更新预览；松开提交一个展示命令，一次Undo撤销。Esc取消；浏览模式按Delete不会删对象。标记菜单中的“删除标记”明确说明资料仍保留。

点击同时拥有对象和子地图的标记默认阅读资料，另有“进入地图”操作，避免单击含义不确定。

### 5.4 图层、搜索与密集标记（WE-007/008）

图层有标题、图例、顺序、默认可见性和编辑锁定。作者设置共享默认值需显式保存；浏览者临时隐藏图层只改个人状态。

搜索对象返回地图内所有标记；一个对象多处出现时列候选。没有标记显示“尚未在地图标注”，不放到原点。若结果处于隐藏层，先询问是否临时显示该层；不能悄悄改共享默认值。

密集标记可聚合或列候选，聚合不是合并对象。文字可随缩放减少显示，但列表仍可访问全部对象。

### 5.5 子地图与专题（WE-009/018/019）

世界—区域—城市—建筑—房间按作者提供的地图互链；各地图拥有自己的逻辑坐标，不要求统一比例尺。地图可从多个入口进入，面包屑按访问路径记录，不自动改地点父子关系。

M1提供折线与简单多边形的基础绘制（画布矢量原生）；M4增加路径说明、分布区和共享专题预设。画范围不自动给内部地点添加文化、政体或组织属性。历史/章节/版本视图只筛选作者已定义内容，不插值和推导中间状态。

## 6. 世界关系网络（WE-010–013/025）

从资料页或地图侧栏选择“查看关联”，默认展开一层明确关系，再按类型和方向扩展。显示人物、地点、组织、物品、事件和锚点，节点仍指向同一内容。

创建关系需要明确两端与关系类型，再填写说明和可选来源。连接拖拽只能打开关系创建草稿，不松手就自动创建不明含义的边。

正式关系、正文提及、关键词命中、自由图形线有不同图例；默认网络只显示明确关系。A信任B不自动画B信任A；隐藏边不删除关系。删除正式关系必须从关系详情执行并查看影响。

图布局可以自动计算或手动调整，但默认属于个人操作；仅“保存专题布局”写共享文档。首版局部展示上限250节点/500边，超出显示截断提示和筛选建议，不假装展示了全部连接。

## 7. 内容创作与故事关联（WE-015–017/024）

新增通用实体编辑器，使用模板而不是为16个领域复制16套复杂窗口。所有栏目可空、可折叠；可以先写名称和一段正文。模板的提示问题帮助思考，不生成事实，也不给未填栏目打低分。

保留既有人物属性与Wiki别名能力；新地点、组织和文化条目参与搜索、正文链接、地图和网络。同一份正文不在地图说明里复制。

历史事件可作为普通资料，不强制可执行；通过明确关系连接参与者、地点和描写它的场景。伏笔、揭示、承诺和回收复用锚点的身份及反查。未回收可标为刻意留白，不自动判错。

内容状态和陈述性质分开显示。例如“已确定的传闻”不能显示成“已证实事实”。无地理位置的思想、魔法原则仍可在内容与网络中完整存在。

## 8. 协作与数据保护（WE-020–023/025）

M1先正确处理文件冲突和保存，M4提供对象/关系/标记批注、正文片段锚定、提案与审阅。批注失锚要提示；提案基线过期需重新比对。

审阅里区分“灯塔归属改变”和“灯塔标记向右移动”。引用影响只显示明确引用，不声称已经找出所有文学后果。地图图层隐藏不是安全权限；本期没有强身份认证的本地文件不能保密给已拿到文件的人。

桌面保存有失败明细和恢复入口；外部修改与本地脏缓冲并存时不覆盖。浏览器保存完整工程包并可存本地快照；没有磁盘实时同步能力。包过大或本地存储失败要保留修改，允许另存副本，不显示虚假的成功。

## 9. 错误与空白态

| 情况 | 用户应看到的状态 | 不允许的处理 |
|---|---|---|
| 没有地图 | 创建入口与说明 | 要求先运行故事 |
| 栅格图层素材缺失 | 占位、图元保留、重新关联素材入口 | 删除地图或所有标记 |
| 对象没有标记 | 未定位列表 | 放在[0,0] |
| 标记引用缺失 | 可见断链提示、重新绑定 | 同名对象自动替换 |
| 地图JSON损坏 | 文件位置、原文修复/另存入口 | 用空地图覆盖原文件 |
| 外部冲突 | 双方差异和保留副本 | 最后写入自动胜出 |
| 局部网络超限 | 截断说明、分组与继续展开 | 删除看不见的节点 |
| 无可执行事件 | 内容正常，试玩入口说明 | 阻止保存世界内容 |

## 10. 质量目标

M1验收负载：1,000内容对象、一张2048×2048栅格图层、500标记与数千矢量图元；M2增加3,000条关系。测试机、浏览器版本与DPI在M0登记。性能目标以[共同契约阈值登记](https://github.com/ikzerok/worldline/blob/cf4cdeac3ed56fb62bf840d5adfc2047d0d5d912/spec/presentation.md)为单源：交互绘制帧P95≤33ms在M1记录不阻断、M2起为发布门；已加载本地对象查询P95≤150ms、暖态资料切换P95≤200ms自M2验收。首次打开和大文件保存另行记录，不混入帧预算。

栅格图层尺寸与内存预算按平台分档，单源见[共同契约阈值登记](https://github.com/ikzerok/worldline/blob/cf4cdeac3ed56fb62bf840d5adfc2047d0d5d912/spec/presentation.md)（桌面≤4096×4096且≤16,777,216像素；WASM默认≤2048×2048）。CPU/GPU副本分别记账。数值是初始安全与验收建议，需原型实测修订；不是对现有代码的性能承诺。

保存/读回、中文路径、缩放定位、一次拖动一次Undo、无内容污染和旧工程兼容为发布硬门槛。其余平台未经GUI验证不得写“已全面支持”。

## 11. 分期交付

M0固定配对版本和测试基线；M1完成矢量画布上的地图阅读/标记与基础线面绘制/图层/保存；M2加入通用实体、跨类型关系、子地图和反查；M3完善16类内容模板与历史叙事；M4完成展示预设、专题、批注及提案。

每阶段都有可用结果，不以新语言全面完成或完整知识图谱为地图前置。具体PR和依赖见[实施计划](https://github.com/ikzerok/worldline/blob/cf4cdeac3ed56fb62bf840d5adfc2047d0d5d912/docs/design/shared/IMPLEMENTATION.md)。

## 12. 最终验收故事

在雾港总览点击城市入口进入城市图，点灯塔阅读资料，进入守灯会关系图，再读灯塔熄灭事件及对应场景，返回城市图；改灯塔名称，各引用处同步；拖一个标记只改其版式；删除它，世界资料和其他标记仍在；保存后桌面与浏览器都能读回。

完成这一过程不需要世界时间、资源、随机判定和人物行为。它展示的是作者已经创造的世界。
