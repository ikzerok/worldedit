# 书稿写作与重组

书稿决定作者的阅读编排，不改变事件执行顺序、世界时间或故事出口。章节引用原有 event、scene、entity；显式语言 1.11 还可引用 fragment。章节 ID 和对象 ID 都是稳定身份，同名标题不会合并。

## 创建首章和继续写作

书稿空页和“新建章节”提供[书稿、章节与正式正文联合创建](start-writing-0.30.md)。先填写书名、章名，再明确选择已有来源或新建 1.9 空事件；预览计划后一次应用，立即进入正文输入。稳定身份与存放位置可在高级项调整，计划中始终明示。

## 从章节直接写正文

选择章节后，主区直接显示当前来源的正文块。默认“写作”模式中，正文可直接输入，控制语句显示为结构提示；内插、显式链接、转义及本地化行标记仍是原始文本，请保留需要的标记。写作模式不执行分支，也不展开片段 call。“结构”编辑当前 event/scene/fragment 的声明体；“源码”显示完整来源文件，便于复杂语句、实体 description 或尚未完成的代码。

三种模式和同文件多个章节共用同一个 core 源文件草稿，不存在独立章节正文副本。切换章节或视图会保留未应用输入。修改正文不会自动提交；点击“应用正文草稿”先验证完整工程，成功后形成一次可撤销修改，再使用保存工程落盘。结构或块输入无法解析时不会丢掉内容，可切到源码继续修复。

完整源码的“应用源码草稿（可含诊断）”是明确的未完成作品通道：允许保存有诊断的源码缓冲，同时保留编译错误提示。它仍校验工程内容基线、工作区只读状态和磁盘变化，不能覆盖外部新稿。只读或无法确认的来源不会启用危险回写。若应用被拒绝，原输入留在草稿中。需要放弃时用“丢弃此文件草稿”并确认；这会丢弃该文件所有章节共用的未应用输入，不删除源文件。

“编排与来源”默认折叠，把摘要、POV、状态、目标和来源选择留给需要时展开。正文字号、行距和阅读宽度使用个人阅读设置，不写入作品。

## 编排章节

- 章节树可折叠分节；列表和卡片显示摘要、POV、状态、静态词数及目标。状态和 POV 筛选只改变显示
- 现有“上移/下移”只调整同父项顺序。新的“移动到分节”可移动章节或整个分节；子项跟随父链，不能移入自身或后代
- “删除编排项”先列出受影响的稳定 ID，确认后只从书稿草稿移除所选项和其编排后代。任何 `.wl` 正文、人物、事件和文件都保持原样
- 新章节不会默选第一个事件，必须展开来源选择器，按名称、类型、ID 或来源搜索并明确选择
- “应用书稿”先预览并校验基线，再把整个编排作为一个可撤销事务提交。未知可选 JSON 字段保留。“恢复书稿草稿”放弃尚未应用的编排，正文文件草稿不受影响

书稿草稿与正文草稿是不同的待应用事务。书稿重组本身不会改变运行指纹；正文内容修改可能改变。外部变化使旧草稿过期时，应保留输入后核对新内容，不应通过反复点击强行应用。

## 阅读预览和恢复

“阅读预览”现在显示[可信全分支审稿](manuscript-review.md)：它是 core 当前稿的只读结构投影，默认明确标记“静态全分支 · 不代表真实路线”。条件分支、选择、嵌套场景和结束边界各自标明，不再把互斥结局排成无局部边界的连续正文。条件不求值，call 不递归展开，去向与 return 保留结构说明。

台词以人物显示名为主，“身份”按钮可查看稳定人物 ID；演出说明置于正文之外。每个具有真实来源的块可“定位原文”，定位到同一源文件草稿的真实 UTF-8 范围。“返回审稿”或 Alt+Left 可恢复原作者位置；不自动应用或保存。过期、坏稿、输入法组合或磁盘来源冲突时拒绝旧来源跳转，完整输入继续保留。

“当前章节”是默认范围；“整书”按编排分批，每批最多 8 章，明确显示当前范围与总章数。未加载章节和超出预算的章节不会伪装成已审完。正文字号、行距、阅读宽度沿用个人设置，链接与前后文字共用一个段落排版流。详见审稿说明。

个人会话记住稳定书稿/章节 ID、正文滚动位置和光标位置。光标同时绑定目标身份、编辑模式、块范围及完整源文指纹；原文或目标变化时忽略旧光标，个人状态不保存正文内容。失效身份不能按标题猜测；这类个人视图状态不写进 `.world/manuscripts`，也不改变撤销记录或运行指纹。

个人会话独立记录“写作 / 结构 / 源码”显示模式。光标只在该模式、完整源指纹与目标身份都相同时恢复；最后曾获得焦点的旧源码光标不会把已经切回写作的页面重新切成源码。返回上一作者位置与跨会话恢复遵守同一规则，旧会话缺少模式字段时默认写作。


## Focus 与 Ledger

Focus 风格将编辑与审稿保持为单一工作区，通过顶部“编辑／预览”切换；“选择章节”“新建章节”“书稿管理”和“阅读预览”始终可召回。它读取外观预览，不覆盖原有个人专注开关或书稿切页偏好。Ledger 以章名作为题签，宽屏侧置、窄屏上置；正文仍来自同一 WritingBuffer，来源与应用边界不变。
## 正文滚动与工具可达

正文的滚动位置只用于文面内容。章节身份、写作／结构／源码切换、应用与丢弃入口位于滚动区外；切换风格不重置有效的长稿位置。短稿不足一屏时，文面高度按实际可用空间计算，不因恢复的滚动偏移增加空白。

极窄或高缩放窗口将正文操作收束为明确的“正文工具”菜单，书稿管理与章节选择保持可召回。长标题受限显示并可查看全文；展开管理内容具有独立的有限滚动范围，不能持续挤占正文。上述布局不改变原稿、未应用输入、输入法组合接收者或原有撤回语义。

编排字段组合输入期间若外部刷新使书稿只读，或工作区出现恢复冲突，当前组合仍可完成并保留在原作者草稿中。应用书稿、调整结构与更改来源继续受只读和冲突保护；完成输入不会提交工程或覆盖磁盘。

## 0.33 从正文关联世界资料

选中章节中的正文文字，在右键菜单或“选词工具”中打开“关联世界资料”。已有资料
按名称、别名、类型/稳定ID和来源分页检索；同名候选分别显示，明确选中后预览，
“插入引用到正文草稿”仍不应用或保存。文字不能无损成为链接标签时会保留原文并
说明原因，不自动改称呼。源码/结构/写作共用同一文件缓冲与精确 UTF-8 选区。

在当前非空选区内右键打开关联菜单时，保留这次明确选中的中文、emoji 和完整范围。
保留仅针对同一编辑器、章节、显示模式、全文基线及草稿代次，并以本次实际排版的
选区位置核对鼠标落点；选区外右键、旧稿或输入法组合不能借旧选区开始新的关联。
已有未完成的关联表单重开时继续原输入和原选区，不因这次右键位置改绑；换选区仍须
使用表单中的明确操作。

“新建人物”创建正式character；“新建实体资料”用于地点、组织、物品等entity。
须明确稳定ID、显示名和资料目标文件。预览显著列出源文件与目标文件中将一起应用
的完整未应用草稿，所有变更文件可逐页查看完整前后源码；其他文件的草稿保留。
默认1.9的新实体必须先勾选预览启用1.10，再核对迁移诊断与存档影响；直到确认
“应用这组关联草稿”前都不升级。一次应用同时提交资料、正文引用及必要清单，
一次工程撤销恢复相关草稿；后续输入冲突时拒绝覆盖。保存另行执行。

正文关联、正文替换与译文应用共用真实操作历史。组合应用所纳入的完整草稿随
该操作撤销、重做，保留原文、未应用文字及草稿代次；交错创建译文文件后逐步
撤销，也不能因待删除文件仍在工程中而丢失草稿。仅插入已有引用的草稿撤销
绑定当时的工程历史节点，不能借相同内容或相同历史条数认作另一分支。
工程历史最多保留40次操作；新分支丢弃重做记录，裁剪时一并丢弃对应恢复资料。
每次撤销、重做先核验完整候选；后续输入、外部刷新或原文不匹配时保留当前
工程、草稿及该次记录，不部分恢复、不消费失败记录。外部刷新明确使旧历史
失效时，保留实际作者草稿。历史操作始终不写磁盘，保存后的撤销仍须另行保存。
普通“应用正文草稿”和“应用源码草稿（可含诊断）”也保存所消费的完整文件草稿；
撤销应用先恢复这份草稿，再可继续撤销其中的引用或替换操作、以及更早的工程操作。
明确丢弃此文件草稿（包括保留草稿入口）会结束该文件跨工程历史节点的草稿级
撤销、重做，并释放不再使用的恢复见证；其他文件草稿和工程操作历史保持不变。
取消丢弃不改变输入或任何历史。“丢弃未应用输入并继续”结束全部文件的草稿级
历史，再丢弃各创作表单；工程操作历史仍由后续明确的工作区动作决定。

“旁查资料”打开现有资料旁栏，正文不离开原章；“返回正文关联”回到原章选区与
滚动位置。关闭、Escape均保留未应用新建输入；“改用当前选区”是明确换目标，
不会因为点了另一个章节就偷偷改原选区。输入法组合期间确认、关闭与候选翻页
不触发。只读、外改、旧代次、被删目标和无效稿不会部分应用，输入始终保留。

窄窗或高缩放时，关联窗口将来源说明收进可展开的“固定选区与来源”，保留选中文字
以及返回、预览、应用的固定操作栏；“更多”中仍可明确更换选区或清除输入。表单、
目标文件与完整计划共用真正受屏幕边界约束的滚动区，末行说明也能完整滚入，不缩小
字号或省略字段。Tab / Shift+Tab 会把新获得焦点的字段滚到可见处；随后用鼠标滚动
或继续输入时，不会因旧焦点把文面拉回。这些布局调整不改变草稿和应用边界。
