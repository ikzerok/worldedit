# 书稿写作与重组

书稿决定作者的阅读编排，不改变事件执行顺序、世界时间或故事出口。章节引用原有 event、scene、entity；显式语言 1.11 还可引用 fragment。章节 ID 和对象 ID 都是稳定身份，同名标题不会合并。

## 从章节直接写正文

选择章节后，主区直接显示当前来源的正文块。默认“写作”模式中，正文可直接输入，控制语句显示为结构提示；内插、显式链接、转义及本地化行标记仍是原始文本，请保留需要的标记。写作模式不执行分支，也不展开片段 call。“结构”编辑当前 event/scene/fragment 的声明体；“源码”显示完整来源文件，便于复杂语句、实体 description 或尚未完成的代码。

三种模式和同文件多个章节共用同一个 core 源文件草稿，不存在独立章节正文副本。切换章节或视图会保留未应用输入。修改正文不会自动提交；点击“应用正文草稿”先验证完整工程，成功后形成一次可撤销修改，再使用保存工程落盘。结构或块输入无法解析时不会丢掉内容，可切到源码继续修复。

完整源码的“应用源码草稿（可含诊断）”是明确的未完成作品通道：允许保存有诊断的源码缓冲，同时保留编译错误提示。它仍校验工程内容基线、工作区只读状态和磁盘变化，不能覆盖外部新稿。只读或无法确认的来源不会启用危险回写。若应用被拒绝，原输入留在草稿中。需要放弃时用“丢弃此文件草稿”并确认；这会丢弃该文件所有章节共用的未应用输入，不删除源文件。

“编排与来源”默认折叠，把摘要、POV、状态、目标和来源选择留给需要时展开。正文字号、行距和阅读宽度使用个人阅读设置，不写入作品。

## 编排章节

- 章节树可折叠分节；列表和卡片显示摘要、POV、状态、静态词数及目标。状态和 POV 筛选只改变显示
- 现有“上移/下移”只调整同父项顺序。新的“移动到分节”可移动章节或整个分节；子项跟随父链，不能移入自身或后代
- “删除编排项”先列出受影响的稳定 ID，确认后只从书稿草稿移除所选项和其编排后代。任何 `.wl` 正文、人物、事件和文件都保持原样
- 新章节不会默选第一个事件，必须展开来源选择器，按名称、类型、ID 或来源搜索并明确选择
- “应用书稿”先预览并校验基线，再把整个编排作为一个可撤销事务提交。未知可选 JSON 字段保留。“恢复书稿草稿”放弃尚未应用的编排，正文文件草稿不受影响

书稿草稿与正文草稿是不同的待应用事务。书稿重组本身不会改变运行指纹；正文内容修改可能改变。外部变化使旧草稿过期时，应保留输入后核对新内容，不应通过反复点击强行应用。

## 阅读预览和恢复

阅读预览为 core 静态文本，不是一条试玩路径；条件分支按源码顺序列出。1.11 的 say 计台词文字，不计 speaker 或作者演出备注；call 显示引用提示，不递归展开片段。规则是计算声明，不作为章节正文。

个人会话记住稳定书稿/章节 ID、正文滚动位置和光标位置。光标同时绑定目标身份、编辑模式、块范围及完整源文指纹；原文或目标变化时忽略旧光标，个人状态不保存正文内容。失效身份不能按标题猜测；这类个人视图状态不写进 `.world/manuscripts`，也不改变撤销记录或运行指纹。

个人会话独立记录“写作 / 结构 / 源码”显示模式。光标只在该模式、完整源指纹与目标身份都相同时恢复；最后曾获得焦点的旧源码光标不会把已经切回写作的页面重新切成源码。返回上一作者位置与跨会话恢复遵守同一规则，旧会话缺少模式字段时默认写作。
