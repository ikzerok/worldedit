# 对象查找与可靠返回

快速导航的“对象”页查找名称、别名、正式类型、ID与定义来源路径；“命令”页只显示
真正可执行的作者任务。对象按完整类型＋ID稳定排列，每页20项，显示精确总数和页范围。
用上一页／下一页或 PageUp／PageDown 遍历；↑↓选择，Enter打开当前可见项，Esc返回。
同名和跨类型同ID不会合并，第二行保留来源目录与行号。

查找与替换窗口中的“工程文件 → 文件与对象”也使用同一对象页。正文命中和对象候选
保持各自的范围；对象总数不等于正文命中数量。引用、关系端点和章节来源等表单使用
同一分页匹配；模板引用类型约束交由core解释，整个目录仍受候选预算保护。

全局对象检索读取当前唯一写作草稿。草稿暂不可解析时明确显示“已应用目录”，旁查
使用已应用对象，不将旧行号套到未应用正文。来源或查询改变会清理旧页并回首页。
真正打开对象前仍核对完整身份和core来源守卫；外部修改、过期来源或恢复冲突会阻止
导航并保留原稿。

输入和翻页不会改变表单已有引用。没有匹配、预算错误、Esc取消也保留原身份；只有
明确选择或“清空”才修改该字段。中文输入法组合期间不确认、翻页或关闭；关闭选择器
回到原控件，取消全局导航回到此前焦点。以上是程序按键事件保护，不能代替具体
操作系统和物理输入法的实际验收。

默认扫描预算10000个目录对象，页上限100。超预算显示错误，不返回部分候选或假总数；
把文字搜得更窄不能绕过完整目录预算。旧地图检索仍使用既有默认匹配范围，不会悄悄
把路径加入地图文字检索。

资料索引、Wiki索引、事件正文“插入对象链接”和源码 `@` 补全也使用同一core页。
这些已应用来源入口明确显示“已应用目录”；`@` 补全可用翻页键遍历并只确认可见项，
插入仍使用原来的core引用事务，不把显示名或临时候选保存为另一个对象。
