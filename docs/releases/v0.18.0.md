# Worldline 与 Worldedit 0.18.0

本版将当前作品的语言与静态资料问题集中到同一个作者工作台，并改善长源码的显示与返回位置。core 是诊断、精度、覆盖、查询和分页的唯一实现；编辑器、CLI 与 RPC 消费同一报告。产品版本 0.18.0，默认语言仍为 1.9，最高既有显式语言为 1.13，不新增 DSL。

## 先理解报告的范围

统一问题报告覆盖当前已应用的活动源码、工作区清单，以及已注册的地图、网络视图、预设、批注、提案、模板、保存查询、书稿、读者发布配置与本地化文档。它只读缓冲，不自动保存、迁移、修复或升级旧作品。

每个检查域分别说明 checked、partial、unavailable 或 not_applicable；有 error 不等于未检查，checked 也不等于无 error。整体 complete/truncated、总计与当前筛选匹配数分别展示。源文件不可读、注册失效、预算不足或旧报告过期时，不用空列表冒充全部通过；原问题消失也不等于已经解决。

span 来源具有 core 验证过的范围；document 只打开那份文档，不把 JSON 验证器的 1:1:1 占位编成精确选择；unavailable 保留原因，不跳到另一个同名文件。显示行列以 1 起 Unicode 字符计，UTF-8 字节范围保持独立。

报告仅编译活动缓冲，未加载的磁盘 include 不会暗中进入结果。content_baseline 绑定已应用稿件，source_observation 是有界路径、可读性与冲突观测，不是安全签名或持续最新保证。报告 ID、问题 ID 与游标绑定具体结果，陈旧定位须重新检查。

## 一个入口，保留各自门禁

状态栏、菜单和命令面板从各作者页打开同一工具。列表按错误、提醒、提示排序，支持严重性、检查域、相对路径/当前文件及文字筛选。虚拟行展示可辨路径，详情提供完整说明、复制、主来源和相关来源分页；窄窗切换列表/详情，不增加永久右栏挤压正文。

原生 F8/Shift+F8 定位下一/上一问题；列表上下键只改变选择，Enter 回源，Esc 按最上层退出。浏览器保留菜单/命令入口，不抢占开发工具的 F8。详情获得键盘焦点时自动滚入，Back 恢复作者来源、有效选区与视口，继续保护未应用书稿和表单。

统一查看没有改变既有阻断策略。`wl check` 仍是活动内容与清单检查；一个展示文档错误不自动禁止无关故事运行。实际导出、发布、保存、只读与冲突检查仍在各自操作执行。读者配置静态检查不等于已核对实际公开选择；本地化交换包的选中字符串过期、缺失和保护 token 检查不在本报告范围内。

## 长源码按窗口折行

“视图”和“阅读与外观”提供同一个源码自动换行开关，默认关闭，保存为设备个人偏好。它只改变 `.wl` 的真实 galley 排版，不插入换行或写入作品。中文、emoji 和长 ASCII 视觉折行后，物理行号仍只在原始 newline 处递增。

改变宽度、字号、行距或折行时保留字符选区及方向。可见光标优先保持，离屏光标用当前视口的逻辑字符锚点保持阅读位置；搜索和明确诊断跳转优先于旧视口。Back 在来源基线仍有效时恢复，布局改变后按当前 galley 重算，不用旧像素或固定行高猜测。文档级 JSON 返回同样保留其真实编辑器位置，但不将源码折行应用于 JSON。

源码选中建档建议只在源码编辑焦点和适当顶层显示；命令、搜索或输入法组合期间不遮挡上层操作。开关、显示变化和来源跳转不隐式应用或丢弃草稿。

## 后台、机器接口与预算

后台每个版本至多一个活动报告任务。原生合作取消后保留唯一槽到旧线程真实退出，再开始最新版本；连续编辑不积累并行工程克隆。Web Worker 结束可立即释放槽。迟到、错任务、旧基线或不匹配观测的回包丢弃，显式取消不会自行复活任务。

一次报告构建至多编译一次；筛选、分页、选择、来源展开和绘制不编译。CLI 使用 `wl problems DIR --json`，RPC 通过 `authoring.problems.v1` 发现 `project.problems`。稳定 partial 可以缓存复用，正在变化的观测强制重建。问题和游标均为 opaque 值，客户端不得自己拼接序号。

core 报告上限为 20,000 条问题、50,000 条相关来源及 32 MiB 编码预算，单段文字 16 KiB、摘录 512 字节；分页默认 50、最多 200 条并受字节预算约束。编辑器请求 16 MiB 报告，为现有 32 MiB Worker 传输封装留空间。超限明确截断，不隐藏完整性状态。

详情见 [工程问题合同](../project-problems.md)、[源码折行合同](../source-wrap.md) 及配对 core 的 `spec/problems.md`、`docs/problems.md`。

## 验证与平台边界

本版采用固定本机样本门槛：331 源文件/1920 实体报告每次不超过 5 秒，5000 问题查询分页 p95 不超过 50ms，offscreen 帧 p95 不超过 40ms，报告与 UI 额外内存不超过 128 MiB。测量配置为 Rust 1.98、默认 dev opt-level=0、debug=0、incremental=0、jobs=2；它不是发行优化性能或任意设备 SLA。

本地 core 完整测试 1079 通过、6 性能项 ignored，editor 默认完整测试 634 通过、6 ignored，均零失败；fmt、严格 all-targets Clippy 与原生构建通过。重复 focused 回归没有累加成独立测试总数，最终配对、WASM/原型及 Windows/main CI 按精确提交的记录独立核对。

Linux 原生实际窗口记录为 1188×848、1280×760、1046×662。实测包括暗/亮主题、16/28 字号、键盘设置与开关持久化、3200 汉字物理长行折行、末端搜索真实选区、问题主/相关来源 Tab 滚入、Enter/Space 零写入及 Back；鼠标与滚轮走通 Book→错误筛选→问题文字行→详情→文档级来源→Back。尺寸不是全平台或所有组合穷举。受 1364×1024 桌面限制，1600×1000 仅在 frame 测试，不冒充实际大屏。

本轮实测并修正了两处输入/显示细节：动画中的内容偏移不能用于比较视口尺寸，否则浮点微差会中断长行定位；来源动作须消费自身 Enter/Space 激活事件，不能把它继续交给刚获得焦点的源码。回归同时核对全部源码字节、dirty、工程版本和撤销深度不变。

固定性能样本：331 源文件报告十次 p50 269.86ms / p95 294.97ms；独立合成 5000 条问题的查询/分页 p95 19.03ms、60 帧布局 p95 0.77ms。同进程真实 5000 条问题的后台报告（compile=1，单次 946.49ms）→安装→60 帧，保守新增 RSS 13.60MiB。真实报告与合成消费样本分开记录，不将不同进程内存相加。

系统 IME、读屏、高 DPI、Windows/macOS GUI 与真实浏览器未实测。合成 IME、offscreen、大尺寸 frame、WASM 构建及 Node Worker 协议都不替代这些路径；Windows CI 不等于 Windows GUI 验收。最终精确配对与发行资产校验见对应提交、CI、release-pair.json 和独立版本报告。

## 0.17 升级兼容实证

- 同源码 fixture 的 0.17 普通 Story save 在 0.18 成功恢复；暂停组选项、后续随机输出和最终状态均与 0.17 自恢复逐项相同。该样本不代表全部旧作品都已验证
- 0.17 entry trace 与 checkpoint-origin trace 在 0.18 均以退出码 2 拒绝，明确报告 trace runtime_version 不兼容。内层 checkpoint 的 runtime_version 守卫也独立验证保持，不能把普通 save 成功推断为 checkpoint 跨版本兼容
- 0.18 新录制 trace 在同版本重放成功。旧记录请保留原工具，或在新版本重新录制；不要修改版本字段绕过保护

升级前保留完整工程与原运行记录。语言版本不变并不取消工具版本绑定的重放约束。
