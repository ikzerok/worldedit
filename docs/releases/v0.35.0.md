# 0.35.0 同一 schema 的资料填写与修错

本版将同一 schema 接入四类资料的填写、预览与修错，配套 worldline/core/runtime 0.35.0。资料填写与机器接口共用 core 投影和事务；作者可在预览中检查诊断及运行指纹变化，再明确应用、保存。

## 从约束到资料表单

本版将既有 schema 接到人物、实体、世界和关系四类资料填写。使用完整对象身份选择目标，显式绑定相容 schema，按同一 core 投影显示字段类型、必填状态、当前值、引用候选和诊断。模板继续是独立的填写提示，不自动变成作品约束。

“未填写”与已经填写的 0、false、空字符串分别显示；必填不等于非空。已有类型错误的原值保留，不自动强转、补默认值或删除未知属性。引用候选由正式 kind 与 entity subtype 约束筛选，不凭显示名或中文错误消息推断身份。

字段诊断与对象诊断保留真实来源，作者可分别定位属性和约束声明。缺失、重复、歧义或不完整来源不能仅因仍有部分可见字段就被当作可写对象。

## 显式预览、应用与保存

绑定、换绑、解绑，以及选定字段的设置或移除，均采用显式意图。先预览完整候选及诊断，再按同一基线与计划摘要整笔应用；预览不改工程，应用只改内存，保存另行执行。字段和绑定跨文件时仍属于同一事务，不先写一部分再补其余操作。

预览提供 core 实算的 `before_fingerprint`、`after_fingerprint`（十进制字符串）及 `runtime_changed`，界面据此提示已有记录需要重新验证或重开。指纹变化时，既有 Story Save 和运行检查点仍受原有守卫约束，不通过改算法绕过兼容性检查。

预览和应用只操作明确选择的字段及绑定，保留未选属性、无关源码和其他文件。来源过期、字段身份变化、外部冲突、未知能力、歧义或预算失败时拒绝结构化写入并保留输入。仍含普通实例约束错误的作者草稿可按明确提示应用；应用或保存成功不代表语义合格，执行与读者发布继续受既有错误门禁保护。

详见 [schema 作者事务契约](https://github.com/ikzerok/worldline/blob/main/spec/schema-authoring.md)。保存后仍打开的旧父资料窗可能因版本守卫显示过期，需要重新打开；本版保留这一保护，不以内容相同绕过版本检查。

## 同稿快照与作者上下文

约束源码工作台与四类表单复用当前已应用工程的同一次编译结果，schema 索引不重复编译或验证。对象投影以完整身份有界缓存；空闲绘制、滚动、折叠、主题和布局切换不应触发新的语义编译。缓存淘汰不丢弃尚未应用的表单输入。

真实源码或编译能力变化后建立新快照，旧投影及旧计划必须重新核验。纯展示变化可能保留编译结果，但事务基线仍须更新。未应用字段不是已应用工程的一部分；读取诊断不抢夺输入焦点或移动光标。

本版复用既有同步编译链，不宣称首次载入或真实改稿没有同步成本。作者上下文沿用现有五布局与配色，区分正文、资料、约束和操作状态；颜色不是错误、只读或过期状态的唯一提示。详细快照边界见 [同稿 schema 快照](https://github.com/ikzerok/worldedit/blob/main/docs/schema-authoring-snapshots.md)。

## CLI 与机器接口

新增 `wl schema-authoring query`、`preview`、`apply` 与 RPC `schema.authoring.query`、`preview`、`apply` 使用同一 core 投影与事务，协商能力为 `authoring.schema_authoring.v1`。目标必须包含完整 kind/id；输入拒绝未知字段、重复 JSON 键及不合法形状。

CLI apply 默认只修改本进程内存，退出后不会自动落盘；仅明确 `--save` 才进入保存事务。RPC 使用已打开的工程，不隐式刷新、恢复保存事务或写磁盘，保存由既有 `project.save` 另行请求。`ok:true` 表示查询或事务成功，不能替代诊断与完整性检查。

请求、字段、来源、引用候选和输出均有明确额度，超限失败，不用截断结果授权应用。保存失败需保留真实的已应用/未保存状态与可恢复事务，不宣称磁盘零写或已经回滚。完整参数、错误码和额度见 [机器接口契约](https://github.com/ikzerok/worldline/blob/main/spec/schema-authoring-machine.md) 与 [作者事务契约](https://github.com/ikzerok/worldline/blob/main/spec/schema-authoring.md)。

## 兼容与范围

本版不新增 DSL 语法，默认语言仍为 1.9，已有 schema 与引用能力继续遵循显式 1.12/1.13 边界；不会自动升级旧作品。schema 声明与四类对象的绑定本身保持既有 runtime fingerprint；属性修改的影响必须按 core 实际计算，不能统一视为静态无影响。既有算法中，世界与人物的标量属性可能改变指纹，实体与关系的标量属性保持指纹；引用值等具体修改同样以实际预览结果为准。解绑保留原有标量属性，不隐式删除资料。此版不改指纹算法，也不因此公开私密资料。

runtime 版本从 0.34 升至 0.35 后，ReplayTrace 与 ReplayCheckpoint 继续按既有严格版本守卫处理，旧轨迹和运行检查点需要重新录制。普通 Story Save 仍遵循自身格式、能力和语义指纹守卫，不能把运行轨迹的版本限制泛化为所有存档失效。

桌面保留现有外改检测和未保存冲突保护；浏览器工作区仍是授权导入快照，不声称持续监视磁盘。有限缓存与预算不构成任意规模实时响应保证。发行身份与具体资产以实际 Release 及 release-pair.json 为准。

## 验证范围与限制

以下本机结果来自完成局部 IME 修复后的产品源码；原生操作与 release 性能探针分别核验。本机语言全量 1941 项通过、11 项忽略；编辑器默认功能集 1509 项通过、9 项忽略，prototype 功能集 1525 项通过、10 项忽略，均无失败。两种编辑器配置的 native Clippy、WASM Clippy 和 WASM 构建分别通过。初次未覆盖默认 debug 设置的构建因空间不足退出 101；后续 Linux 测试才使用显式 debug=0、incremental=0、jobs=2 配置；这些计数分别属于各配置，不相加为独立用例总数。

完整 App 事件回归覆盖 100%/200% 下的键盘编辑、长字段导航、enum/ref 选择、预览应用、IME 保护、来源返回，以及滚动后空闲不回弹。正文焦点识别修复后，窗口标题与八方向 resize 控件不会被误当作正文控件触发正文滚动。相关测试使用完整 App 的无头事件路径，不等于物理键盘、系统 IME、原生读屏或浏览器端到端认证。

原生验证分阶段完成四类 schema 绑定、label 填写、预览、应用与保存，并在独立磁盘副本中重新打开四类资料，读回绑定及保存值。实体撤销/重做与五种布局作有限代表检查；这些结果来自多个明确绑定的运行阶段，不是一条不中断的单次全流程。有效模板的 count/note 同 key 提示可见且使用共享字段入口；模板独立 extra 字段未作原生验证。

工作表修复了 IME 启停生命周期事件导致刚获焦按钮临时禁用、丢失焦点的问题，仍保护真正的 Preedit/Commit 组合输入。最终未插桩原生候选已逐步验证从 label 经 Remove 到下部控件，输入 note、选择 enum 的 town 与引用 entity:council，明确预览、应用、保存，再通过真实工程菜单从磁盘重载并重新打开表单。三个修改值与 false 在重载后同框可见；count=0、未知属性及其余原文由精确字节核对和独立 CLI 读回确认，不声称它们都在最终截图中可见。

本轮原生验证使用 ASCII 键盘输入，未实测物理输入法、系统文件选择器取消、原生读屏或真实浏览器端到端操作。机器事件回归与 WASM 构建结果不替代这些边界。

release 模式的串行机器探针覆盖 1000/10000 对象与引用候选，缓存读取及 120 个 headless 空闲帧的视图语义编译增量为 0。10000 对象下首次载入约 2.53 秒、字段预览约 1.09 秒、应用并重建约 3.22 秒；真实改稿仍有同步成本。上述为特定夹具与机器上的同步调用耗时，不是原生 FPS、输入延迟或任意规模实时保证。
