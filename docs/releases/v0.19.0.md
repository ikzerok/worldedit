# Worldline 与 Worldedit 0.19.0

0.19 把“看见问题 → 理解原因 → 回到当前稿修改”接起来：core 提供正式诊断生产入口的原稿来源证据与有界上下文，编辑器在现有问题工具和来源页中展示同一份证据。产品版本为 0.19.0；默认语言仍为 1.9，最高既有显式语言为 1.13，没有新 DSL。

本文说明本版能力和兼容边界。最终配对门禁、测量数字与真实平台覆盖尚待下文回填；文档更新不等于已经正式发行。

## 1. 诊断指回它真正所属的原文

诊断生产者分别记录具体目标、完整表达式、语句上下文、声明上下文、文档身份或来源不可用。主位置与每个 related 独立提供证据，同一错误码的不同生产入口不被强行压成同一种范围。

词法与解析阶段保留真实物理输入文件及原稿端点，表达式来源按正式 AST 的 owner/slot 顺序传给分析，不靠格式化表达式、同名词搜索或中文 message 反推。包含纯 literal 运算、嵌套参数、同一行多次插值、choice 的标签/if/enable、else-if 条件与动态 become 各自来源；带引号的规范化文本映回原文两端，不把转义字符截成一半。

include 合并后的执行语句保留真实文件归属，不能按同 basename、同 Loc 或第一次出现顺序猜测。无法证明的语句局部降级，不连带抹去无关声明的可靠范围，也不通过改变解析接受/恢复规则来隐藏问题。各活动编译诊断生产入口的实际覆盖与角色见配对 core 的 [生产者矩阵](../../../worldline/spec/diagnostic-sources.md#3-生产者覆盖矩阵)；这是来源合同，不是所有错误恢复分支均已运行的声明。

位置精度仍仅为 span / document / unavailable。前四种角色只有范围真实且有效时才能成为 span；完整语句/声明可以是准确的上下文，不冒充错误单 token。document 不捏造命中，unavailable 明确保留原因。行列在界内本身不能证明归属。

## 2. 读得懂的有界来源上下文

问题报告 schema 仍为 1，`ProblemLocation` 加法新增可选 `context`，其版本为 1。0.19 产生的主/相关位置均保留角色，即使位置不可用或摘录预算为 0。

`context.text` 严格来自原稿切片；slice 范围是摘录在原稿中的位置，hit 范围是完整命中与摘录的可见交集。原位置的权威 byte/char 范围不会因为摘录缩短而改变。行列为 1 起 Unicode scalar，原始 UTF-8 半开字节范围与 scalar 范围独立；不是 UTF-16、grapheme 索引或屏幕列数。CRLF 按真实物理行处理。

摘录默认/上限为 512 字节，调用方可降低到 0。窗口围绕命中，沿扩展 grapheme 边界显示，避免割裂组合字、肤色修饰或 ZWJ emoji。放得下时包含完整命中；过长时显示非空交集并标 partial，连一个显示单元也放不下时为 no_text，不超支。显示窗口可以包住完整 grapheme，权威命中端点不因此扩大。

界面分别标注前文/后文省略、完整命中、部分命中或没有摘录。省略符和强调不写进原文；“复制原文摘录”只复制 core text。文档级位置不生成假的局部 hit，其 full/partial 只表示全文是否显示完整。兼容 excerpt 与 context.text 相同，重复字节也纳入预算。

## 3. 现有工具里的当前问题

从状态栏、视图菜单或命令进入同一个工程问题工具，继续使用原列表、详情、筛选、F8/Shift+F8、主/相关来源和作者返回历史。没有新增常驻右栏或第二个问题列表。

显式成功定位后，来源页标题下显示可折叠“当前问题”：严重性、原因摘要、主/related 身份和精度/角色。“回到问题详情”返回完整原因、说明、建议及全部相关证据；“复制原因”保留一个直接动作。当前问题身份来自报告及成功定位，不从 TextEdit 选区猜测。

经 core 当前稿验证的 span 获得轻量行侧锚点和温和范围强调，位置来自本帧真实 galley 字符映射，随软换行、字号、中文、emoji 和组合字重排。装饰独立于人工编辑选区；document/unavailable 不画猜测范围。

诊断程序定位仍可按既有行为选择原文，但不会自动弹出“从选中文本建档”。关闭/重开问题工具或 Back 恢复同一次程序选择仍受抑制；真实鼠标/键盘人工选择恢复原有建议、批注与 Ctrl+Enter。显式 Ctrl+Enter 的作者动作不被被动建议抑制替代。

光标移动不抹去当前问题，文字更改当帧撤下旧强调。新报告替换、过滤丢失条目、外部来源变化、检查失败或取消会保留待重检/需重新选择说明，不宣称已解决。Back 恢复视图、有效选区方向、滚动、未保存内容与撤销链；只有同一报告和来源基线仍有效时才恢复上下文。

主题、字号、行距、软换行及后台结果变化不请求编辑焦点，不复活已消费的跳转和选区。IME、未应用正文/表单、外部冲突与原有受保护弹窗继续使用原保护，不隐式应用、保存或清空草稿。

## 4. 详情阅读和界面状态

详情顺序是问题 → 说明/建议 → 来源证据 → 技术信息。原因、说明、建议、摘录与当前问题摘要使用同一份个人阅读字号与行距；code、路径等技术信息可以次级显示，不用固定微小文字承载主要原因。

严重性保留形状和中文标签，焦点、hover、选中与状态有各自表达，不整段铺红。普通阅读文字的对比验收目标至少 4.5:1，必要焦点/状态边界至少 3:1；要按实际 normal/hover/selected/focused 表面核对。颜色计算或 offscreen 断言不等于读屏、高 DPI 或全面无障碍认证。

窄窗保留列表/详情切换、可聚焦筛选入口与直接返回动作，上方正文至少 240 点，底部工具最高不超过可用高度 55%。详细操作见 [工程问题工作台](../project-problems.md)，实现和验收合同见 [当前稿里的问题上下文](../diagnostic-source-workbench.md)。

## 5. 同稿校验、旧报告和机器接口

来源上下文绑定 report 的 content_baseline / source_observation，并参与 report_version 摘要。导航沿用路径、基线及观测守卫，再校验 schema/context 版本、报告摘要和位置证据，从已加载缓冲重投影并严格比较整个位置 DTO。篡改角色、合法但替换过的 span 或局部 hit 范围不能把导航引向另一处原文；不匹配返回 STALE_REPORT。摘要不是安全签名。

新实现可只读显示、查询及分页读取没有 context 的旧 schema 1 报告；第一次导航要求刷新重建。未知 schema/context.version 不被视为当前可导航报告，不能靠默认字段或忽略 context 比较放行。项目已测试的旧 DTO 可忽略新增 context 字段读取新响应，此承诺不覆盖任意第三方 strict JSON 实现。

RPC initialize 新增工具能力 `authoring.problem_source_context.v1`，继续使用 `authoring.problems.v1` 与 `project.problems`；CLI 继续使用 `wl problems`，由 context.version=1 标识加法输出。没有新必需请求字段或额外协商，不改变未知字段/重复 key 拒绝、游标与退出码。

旧 Diagnostic JSON 的八字段形状、诊断事实、code、severity 和运行含义不变。原稿来源修正会改变错误的旧 Span 值；明确无可信来源的编译诊断用 line=0 无效哨兵，不能夹取到首行。新工具能力不进入作品语言能力、required_features 或 Story save。

当前报告只检查已应用的活动缓冲。未载入/未激活源码不能为摘录偷偷读盘；未应用表单与 IME 草稿不属于报告。source_conflict 或 external_observation_changed 时拒绝位置导航，仍可阅读原因；不把所有 partial/truncated 报告一律禁用。

## 6. 完整传输预算与有界工作

- core 完整 report 硬上限 32 MiB，调用方可降低；context 元数据和旧 excerpt 重复内容全部按真实序列化计算
- 主/related 页各不超过 1 MiB；`wl problems` 和成功解析并识别为 `project.problems` 的 RPC 方法响应，成功或失败的完整 UTF-8 JSON 加一个 LF 也各不超过 1 MiB
- RPC 计入 jsonrpc、原始 id 的实际 JSON 编码及 result/error 外壳。仅 project.problems 的巨大 id 若连最小错误都无法回显，则零方法执行返回 -32600、id:null 与 request_id_exceeds_response_budget；可回显 id 原样保留，通知仍无响应
- CLI 超长错误详情保留原 error.code 和退出码 2，只缩短 message。RPC 超长业务详情采用紧凑 BUDGET_EXCEEDED，过长协议详情保留原协议 code；其他方法不改变
- 编辑器 native/Web 沿用 16 MiB report 请求预算，为 32 MiB 完整 worker WorkOutput JSON 保留空间；通用 worker 保持请求 options 与响应 limits 一致，不暗中降低预算

达到预算时使用明确截断或 BUDGET_EXCEEDED，不静默丢角色，不用空页冒充成功。一次报告至多编译一次，查询、分页、来源验证和绘制零编译。绘制只消费当前有界摘要/上下文、可见行和当前源码 galley，不逐帧构建全问题副本。

完整机器使用与限制见配对 worldline 的 [问题指南](../../../worldline/docs/problems.md)、[来源上下文合同](../../../worldline/spec/problem-source-context.md)。两仓相对链接用于同级检出。

此整行上限是上述问题方法的边界，不是全局 JSON-RPC 解析器保证。巨大重复 key 等在方法识别前发生的通用 JSON 解析失败仍走原协议错误路径，不属于本版方法响应预算承诺。

## 7. 语义和升级兼容

本版仅改变诊断来源元数据、错误的坐标投影及工具显示。不增加可接受语法或诊断事实，不改变类型、引用、控制流、世界或运行语义。来源侧表不进入 fingerprint、expression_signature、choice signature、once 身份或 Story save required_features；runtime_version 守卫不放宽。

本轮已取得的兼容实证分别是：

- 同源码 fixture 的 0.18 普通 Story save 在 0.19 加载并完整继续执行；该结果限于实测样本，不代表所有旧作品均已验证
- 旧 trace/checkpoint 仍受原 runtime_version 守卫约束，不能因普通 save 可继续而宣称跨工具版本 trace/checkpoint 可重放
- 0.19 新录制 trace 在当前 0.19 重放测试通过；这不等于跨版本 trace 重放通过

升级前保留完整工程与原运行记录。需要旧 trace 的精确重放时保留原工具，或在新版本重新录制；不要修改版本字段绕过守卫。

## 8. 明确不包含的能力

本版没有自动修复、永久 issue ID、跨稿件同一问题追踪、第二个语言解析器、全恢复分支测试承诺或面向任意客户端的 strict JSON 兼容承诺。合法坐标、相同 code、同文案或列表消失都不能代替来源证据和修复确认。

统一查看仍不统一阻断。保存、试玩、导出、发布、只读与读者白名单各用原门禁；读者配置静态通过不表示实际发布已获准，本地化静态问题报告也不代替选中字符串交换检查。旧工程不自动升级语言或迁移。浏览器工程仍是导入快照，不宣称持续监视磁盘；本版也不增加云协作或可玩网页故事导出。

## 9. 最终门禁与平台记录（待回填）

### 固定样本性能

0.19 冻结样本为 129 源码、2,076,104 原文字节、3072 问题。热身后十次独立 debug CLI 报告构建每次不超过 1.6 秒；界面预热 60 帧后绘制 p95 不超过 40ms，装饰相对无装饰的峰值 RSS 增量不超过 32 MiB。目标不是测量值，也不是发行优化性能或任意设备 SLA。
