# 同类产品能力对标与改进建议

调研日期：2026-09-26。状态：研究建议，非已实现功能清单；本文件仅记录能力研究；界面视觉优化为另一项独立需求。

代码核查基线：worldline `889febe99f7999f8da4c28583320da61e6be13e2`；worldedit `218d0ed5dbda70b4ce803aaae36197905d1a9708`。

## 1. 比较方法与结论

比较对象是世界设定管理、小说创作、交互叙事编辑器的功能能力，不以通用任务软件的配色作为能力对标。
竞品依据为官方功能页、帮助文档与项目说明；未对所有付费产品做登录后的逐功能实测，亦不把官网性能宣传当作独立基准。不同付费档位不在本次评价范围。
本项目依据为当前源码与文档核查，不能把旧 README、规划文档或历史“65 项 PASS”直接当作与竞品功能对等的证据。

核心判断：本项目已有对象、引用、地图、关系、偏序时间线、状态演练和写入保护的基础；下一阶段应补连续创作流程、内容生产工具和对外交付，而不是继续增加同级菜单。

## 4. 建议优先实现的能力包

下面的 P0/P1/P2 是本次建议的顺序，M/L 是相对工程规模，不是排期承诺。编号 CAP-* 仅为文档提案，未创建 GitHub 工单。

### CAP-01 就地建档与引用编辑（P0 / M）

目标流程：写到“白塔议会”时，输入 @ 或选中文字，选择已有实体或创建新实体；确认后插入稳定引用并回到原文。地图同样允许“新建地点资料并放置入口”。借鉴 [S1][S7]。
验收：同名候选显示类型/ID；新建对象、显式正文链接及可选地图标记在一个候选事务中校验；取消零写入；一次撤销恢复；对过期原文拒绝覆盖。
注意：提及不是语义关系。就地建档不能自动生成“成员属于组织”“地点位于地区”等事实；继续复用 core 写入与引用保护。

### CAP-02 书稿与章节工作台（P0 / L）

目标流程：按卷/章/场景组织文稿；为章节维护摘要、视角人物、草稿状态与字数目标；写作时钉住资料；按作者选择的阅读次序生成预览。借鉴 Campfire 与 novelWriter [S4][S15–S16]。
验收：调整书稿顺序不修改事件时间偏序或运行出口；章节引用已有正文，避免复制真源；保存重开保留顺序/状态；中文计数口径明确区分字符和词；长文、链接及未知字段保持保真。
关键设计：阅读编排、世界时间、执行路径是三套不同语义。先完成结构化纯文本编辑和预览，不为了富文本一次性替换全部存储。

### CAP-03 资料库组合查询与待办（P0 / M）

目标流程：查出“某组织相关、仍为草稿且缺少来源的条目”，保存为常用集合；统一列出断链、待建词条、失锚批注、待审提案。借鉴 World Anvil 的组织/待办与 articy 的查询 [S1][S9]。
验收：查询基于当前缓冲；条件可见且可组合；保存查询与个人收藏不改变内容语义；大结果分页；点击结果能到达对象和真实源位置；缺少来源只作资料完整性提醒，不判定自然语言事实真伪。

### CAP-04 可视化审稿与持久历史（P0 / L，可拆分）

优先把现有提案扩展为 base/current/proposed 三栏，按对象属性和正文段落显示差异，附引用影响；随后增加按文件/对象浏览的本地检查点。借鉴 [S4][S9]，复用已有三方合并而不是在 UI 重写规则。
验收：无需读原始 JSON 即可理解修改；同字段冲突无默认赢家；存在冲突时零部分提交；接受内容与提案状态原子更新；历史恢复也做当前基线检查；检查点有容量限制，不以自动覆盖作者原文件实现“自动保存”。
最小增量可先做逐段差异与冲突定位，持久历史单独交付，避免把已有安全写入能力误说成完全缺少。

### CAP-05 工程级可定制模板（P1 / L）

让作者保存、复用、导入工程模板：文本、数字、布尔、枚举、对象引用、栏目分组与可选校验。内置 16 类作为起点，不是上限。借鉴 [S5][S9]。
验收：模板文件有版本；UI 按 widget 类型渲染；未知字段往返；改字段定义先预览影响；删除模板不删实例内容；不执行模板脚本。工程自定义字段类型先更新 core/spec，不能仅在 UI 硬编码。

### CAP-06 可重放的叙事调试器（P1 / L）

目标流程：保存一条选择路径和随机种子，改稿后重新运行该路径；显示步骤前后的变量差异、当前节点和某选项不可用的原因。借鉴 Inky 与 articy 模拟 [S10][S14]。
验收：标明本次演练版本；路径节点/选择失效时停止并定位，不静默选替代分支；重放不能重复污染工程；“从此处测试”必须声明初始状态，不能绕过条件后声称完整故事有效。
覆盖报告是后续深化项：先标记本次访问过的节点，再扩展多个测试路径的合并覆盖；不要承诺一般程序的所有路径可穷尽。
### CAP-07 面向读者的交付与迁移（P1 / L，可拆分）

先提供 Markdown 导入和独立静态阅读包，再考虑 DOCX/EPUB。阅读包按明确选择的对象/书稿导出；不是将完整作者工程直接给读者。借鉴 [S4][S12][S14]。
验收：导入先预览、同名不自动合并、引用可追踪、失败不部分写入；发布包明确列出包含/排除内容；隐藏资料不能从搜索索引、资源文件或源码恢复。完整备份与公开发布是两个不同命令。

### CAP-08 专题投影：人物弧线、家族树与历法（P2 / L）

在明确关系类型映射之后，提供家族/组织专用视图；以人物或地点浏览相关历史，整理人物弧线。自定义历法另立格式契约，不改变现有偏序语义。借鉴 [S2][S3][S6][S7]。
验收：图形排列不产生事实；族谱使用作者确认的亲属关系；养亲/生亲/不同版本能区分；缺失或有争议的日期允许保留；不引入被现有契约排除的世界时钟与自主模拟。

### CAP-09 游戏生产接口（按目标选择 / P2）

当产品明确面向游戏团队时，再推进引擎导出、本地化字符串 ID、台词审阅和批量校验。借鉴 articy 与 Ink [S9–S11][S14]。不把这些成本强加给纯世界观写作者。

## 5. 推荐顺序与两项需求的边界

功能能力调研和编辑器视觉优化是两个独立交付。本文只定义能力差距与候选工作包，不将任何 CAP-* 记作已经实现，也不以界面美化代替能力补齐。
推荐先做 CAP-01、CAP-03、CAP-04 的最小审稿增量；书稿 CAP-02 单独设计内容引用格式；随后推进模板/调试/读者发布。CAP-08/09 根据用户实际创作方向决定。
本轮界面美化独立验证：导航和操作层级、文字排版、间距与色彩、窄窗口适配、键盘和焦点状态；不修改世界语义，不先等上述新能力全部开发完成。

## 6. 不应直接照搬

不因竞品有云服务就把本地文件改为必须联网；不将地图显隐用作保密；不默认从自然语言猜测关系事实；不把精确日历强加给不确定历史；不把保存/冲突保护移到 UI 自行实现。
已有的稳定引用、分域语义、未知内容保真和保守冲突处理应作为继续扩展的底座。
