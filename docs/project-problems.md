# 工程问题工作台（0.19）

从工程问题找到当前稿里的真实来源，再读清原因、修改和重新检查。0.19 沿用同一个问题工具，增加来源页里的当前问题摘要、独立位置强调和有界原文证据。诊断事实、来源精度、查询与报告覆盖始终由配对 worldline core 提供。

## 打开和筛选问题

状态栏的内容错误/提醒和工程报告状态、视图菜单、命令面板及原有“显示诊断栏”设置都打开同一个工具，从各作者页可达。工具在正文下方，可调整高度；宽窗并排显示列表与详情，窄窗在两者间切换并保留选择，不增加另一个常驻右栏。

工具保留上方至少 240 点正文，底部最高不超过可用高度的 55%。较矮时从“筛选（全部／N项）”进入筛选，不以隐藏详情动作换取空间；导航与参考仍遵守原有正文宽度预算。

1. 按严重性、检查域、相对路径/当前文件或文字筛选
2. 在列表中选择问题，读完整原因、说明和建议
3. 在“主位置”或某个“相关位置”查看来源证据，再明确定位
4. 修改后等待重检或显式刷新，核对新报告的范围和状态

列表使用可辨路径、严重性形状及中文名，技术 code 次级呈现。总计、当前匹配数、分页和覆盖范围分开；“无匹配”不等于“工程全部通过”。checked 表示在支持的静态范围内检查过，不保证没有 error。partial、truncated、过期、失败或读取不到来源都需看原因。

## 读懂精度、角色与摘录

位置精度仍是三类：span 有当前原稿中经 core 验证的真实范围；document 只定位文档，不选择虚构的第一个字符；unavailable 显示原因，不夹取到有效行列，也不改跳另一个同名文件。

0.19 另显示范围的含义：具体目标、完整表达式、语句上下文、声明上下文、文档上下文或来源不可用。一个完整表达式或整条语句可以是可靠来源，不代表错误只在其中某个单词。主位置与每处 related 的角色独立；编辑器不按 message、code、同名文本或缩进猜测范围。

详情先显示问题，再显示说明/建议、主/相关来源证据，最后显示技术信息。原因、说明、建议、摘录与当前问题摘要共用“阅读与外观”中的个人字号和行距。严重性始终配合形状和中文名；焦点、选中与 hover 不仅靠颜色区别。

摘录只显示 core 给出的原文，默认最多 512 UTF-8 字节。完整命中放得下时显示完整；过长时注明“当前仅显示可见交集”，前后省略分别提示。“复制原文摘录”只复制实际原文，不把省略提示或强调符混进去。预算不足或来源不可用时可以没有摘录，但角色仍保留；无摘录不等于没有问题。

文档级摘录没有伪造的局部命中。旧版或未知上下文只供阅读，须刷新检查后才可定位。摘录长短不改变来源的完整权威范围；Unicode scalar 坐标、UTF-8 字节和显示窗口各自有明确含义，不能用画面上的字符宽度推算位置。

## 回源后继续理解和修改

成功定位主位置或 related 后，来源页标题下出现可折叠的“当前问题”：严重性、主/相关位置、来源精度/角色与原因摘要。可用“回到问题详情”回到原工具，或“复制原因”。完整说明、建议和所有 related 仍在既有详情，不产生第二份问题列表。

只有经过 core 当前稿验证的 span 才显示轻量行侧锚点和温和命中强调。标记按本帧真实文本排版定位，随软换行、中文、emoji、组合字、CRLF、空行和字号变化重排；document/unavailable 不绘制猜测范围。

位置强调独立于编辑选区。诊断跳转仍可能选中文字，但这次程序选择不会自动弹出“从选中文本建档”；关闭问题工具、再打开或 Back 恢复同一次程序选择，不会把它变成人工选择。用鼠标或键盘重新人工选字后，原有建档建议、批注及 Ctrl+Enter 继续可用。显式 Ctrl+Enter 仍是作者动作，不因被动建议受抑制而被禁用。

移动光标不取消当前问题身份；作者可继续修订。源码一旦变化，当帧撤下旧强调，摘要显示待重检。外部来源变化、检查失败/取消、过滤丢失条目或新报告替换也不会继续使用旧范围，不从消失推断“已解决”。完成输入并刷新/重检，再从新报告定位。

主题、字号、行距、软换行或后台结果变化不会请求编辑焦点，也不会重放已经消费的跳转或旧选区。显示、强调和复制不会改源码、dirty、保存基线或撤销记录。

## 键盘、返回与草稿保护

- 列表 ↑/↓ 只选择，Enter 定位主来源；原生 F8/Shift+F8 定位下一/上一问题。浏览器使用菜单/命令入口，避免抢浏览器快捷键
- 详情动作可用 Tab/Shift+Tab 到达，用 Enter/Space 激活；动作消费自己的激活事件，不向刚显示的源码写入空格或换行
- Esc 按既有层栈返回：窄窗详情先回列表，再关闭工具并恢复开启前焦点；过滤框获焦时上下键不抢文字输入
- 主来源 → related → 作者 Back 沿用作者历史，保留原视图、有效选区及方向、滚动、未保存内容与撤销链。只有报告和来源基线仍相同时才恢复当前问题上下文
- IME 组合、未应用正文/表单与外部冲突继续受到保护。摘要不会把这些草稿认作报告来源，也不隐式应用、保存、清空或合并输入
- A213 仍可进入原有时间环与下游证据入口；问题工作台不自造另一组根因或下游计数

## 后台检查和当前稿边界

报告只包括已应用工程缓冲。未应用表单、书稿/IME 草稿与磁盘未保存状态分别说明；独立 CLI 不读取正在运行的编辑器草稿。未载入/未激活的磁盘 include 不会为摘录被暗中读入，先显式刷新工程再检查。

一次 report build 至多编译一次，筛选、分页、选择、来源展开及绘制不编译。每个已应用版本最多一个自动活跃任务；输入稳定 250ms 后刷新，显式刷新/取消保留原有入口。取消或失败保留旧报告并标过期，不变成完整空报告。

原生取消是合作式退出：等待旧任务真实结束才启动最新版本，不积累并行 Project 克隆。Web Worker terminate 后可释放槽。回包须匹配 generation、工程基线、任务身份与来源观测；切工程或继续编辑后到达的旧结果丢弃，显式取消不会自行重启。

core 的有界来源观测每秒核对一次，附件可读性、根路径或已知冲突变化可触发重检；它不保证实时磁盘全文一致。已知来源冲突或观测变化的报告可以阅读，但不能继续定位。其他部分/截断报告中仍有充分当前证据的位置不一律禁用。

## 接口、限额与旧报告

报告仍用 schema 1，主/相关位置的可选 context.version=1 与 core DTO 同源。没有 context 的旧报告能只读显示、查询和翻页，第一次导航需刷新；未知版本不按当前证据放行。项目已验证的旧 DTO 能忽略新增响应字段，但不保证所有第三方严格 JSON 客户端。机器接入详见配对 worldline 的 [问题使用说明](../../worldline/docs/problems.md)。

core 完整报告硬上限 32 MiB，主/related 页和 CLI/RPC 完整 JSON 加一个 LF 各限 1 MiB；新元数据和旧 excerpt 重复文本都计算在内。编辑器原生/Web 请求 16 MiB report，为完整 worker WorkOutput 的 32 MiB 上限保留空间；worker 检查整个外壳，不能只检查裸报告。快照仍受 10,000 文件/128 MiB 限制。超限显示明确截断或预算错误，不隐藏完整性状态。

## 不属于本工具的承诺

本工具不增加 DSL、诊断事实、自动修复、永久 issue ID、第二份解析器或统一阻断策略。默认语言仍为 1.9，最高既有 1.13；保存、运行、导出、只读及读者公开授权继续分别检查。静态读者配置通过不代表实际发布已获准，本地化静态报告不代替交换操作的选中字符串验证。

当前版本能力、普通 save 与 trace/checkpoint 兼容、最终验收状态见 [0.19 发布说明](releases/v0.19.0.md)。真实 Linux native、offscreen、真实浏览器、Windows/macOS GUI、系统 IME、读屏与高 DPI 必须分别核对，测试或颜色计算不等于全面平台/无障碍认证。实现合同见 [当前稿里的问题上下文](diagnostic-source-workbench.md)。
