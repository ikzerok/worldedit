# 工程问题工作台（v0.18）

状态：R4 实施前冻结的交互及验收合同。诊断语义、查询、来源精度和报告覆盖状态以同级 worldline 的工程问题规范为唯一真源；本文不增加语言、运行或发布门禁。

## 入口及范围

- 状态栏的内容错误/提醒和工程报告状态都是可聚焦入口；视图菜单、命令面板和旧“显示诊断栏”设置打开同一个工具，从每个作者页均可达。
- 工具在主视图下方，独立调整高度，避免额外右栏挤占正文；宽窗列表与详情左右相邻，窄窗在列表/详情之间切换并保留选择。导航、固定参考仍按主内容至少 512 点的现有预算临时收起导航；问题工具不再额外消耗横向宽度。工具保留至少 240 点上方正文，窄窗工具最高不超过可用高度 55%。
- 内容编译通过只说明既有内容门禁。全工程报告另示未就绪、刷新中、过期、部分覆盖、截断或读取失败。报告只包括已应用工程缓冲；未应用表单、书稿/IME 草稿与磁盘未保存状态单独明确。
- 保留时间问题入口。A213 详情可进入既有时间环原因与下游证据，不在工作台自行增加根因或下游问题数。

## 筛选与信息层级

- 严重性、域、相对路径/当前文件、文本使用 core 查询；总计、匹配数、页区间和实际检查覆盖范围分开呈现。空筛选显示“无匹配”，不能写“工程全部通过”。
- 较矮的问题工具把筛选放到可聚焦“筛选（全部／N项）”入口，仍使用同一组core查询条件；列表／详情保留实际可见空间。正文至少240点及工具不超过可用高度55%的预算不放宽。列表键盘提示固定占位，焦点转移不改变面板高度；详情动作只在新获焦点时滚入，不持续抢手动滚动。
- 紧凑列表使用虚拟行，仅布局当前可见行；每行显示严重性图标及中文名、摘要、完整可辨相对路径和 core 提供的位置精度，技术 code 次级展示。
- 选中详情显示完整 message、note、suggestion、可复制信息、主位置及全部 related 的有界续页，摘录只取 core 结果。所有定位先验证当前报告基线。
- 文档级问题显示“仅文档位置”，可以打开文档但不选择虚构的第一个字符；不可用位置显示原因，不能夹取到有效边界。不得用中文文案解析 JSON 坐标，不得按 basename 合并。
- 报告更新后，旧选择只在 core 明确身份仍有效时保留；否则留出“原选中问题不在当前结果，请重新选择”的说明。不从列表消失推断“已解决”，尤其 partial/truncated、注册失效、读取失败和过滤变化。

## 键盘、返回及草稿

- 工具列表有独立焦点，↑↓仅选择；Enter 定位主来源。F8/Shift+F8 为下一/上一问题并定位，只在原生端启用，浏览器以明确菜单/命令为通用替代，避免抢浏览器开发工具绑定。
- IME composing、Preedit、Commit 和原有受保护顶层弹窗继续阻止全局快捷键。过滤文本有焦点时上下键不抢占文字输入。
- Esc 遵守现有层栈：窄窗详情先回列表，再关闭工具并恢复开启前焦点。焦点框、整行选中、hover 和严重性各自独立，不仅靠颜色。
- 主来源→related→作者 Back 使用既有定位/返回历史，保留文件、逻辑选区、滚动和草稿；不隐式应用、保存或清除输入。工具的筛选与选择不因回源被清空。

## 后台与预算

- 每个已应用工程版本最多保持一个自动活跃 report build；取消或失败后允许作者显式刷新重试，不把“最多一次”当成版本锁死，原生线程与 Web Worker 共用 core report API 和可序列化 DTO；筛选、选择、翻页、绘制均不 compile。
- recompile/展示文档修改只标记旧报告过期并取消旧任务；输入稳定 250ms 后刷新。切工程清空结果和游标；回包必须同时匹配 generation、工程基线及任务身份，迟到回包丢弃。
- core 的 source_observation 零编译范围观测每秒核对一次；附件删除/恢复、可读性或根路径变化触发重检，无法读取时旧报告不可称新鲜。WASM 的 live 与 worker 根均为 /world，并随快照一并核对观测 key。
- 原生取消是合作式退出：旧任务若仍在编译，保留其 receiver/唯一 slot 到真实终态，再运行最新待检查版本；连续编辑、切工程、取消或重试均不得积累并行 Project 克隆。WASM 已 terminate 的 worker 可立即释放。显式取消后，旧终态不得自行触发新检查；作者重试只排队最新版本。
- 用户可显式刷新/取消。取消或失败保留已显示旧报告并清楚标过期，不能当完整空报告。关闭工具不取消已经可用报告缓存；后台仍按版本护栏更新状态栏。
- 构建条目/字节/摘录/时间预算以及 cursor 校验以 core 合同为准；传输另沿用快照 10,000 文件/128 MiB、JSON 32 MiB 上限，不因 UI 隐藏截断说明。

## R4–R6 验收记录要求

1. 核心/协议：同一报告 native 与 WASM DTO 往返一致；一次 report build compile≤1；筛选/选择/翻页 compile=0；取消、坏基线、错任务型、迟到回包、文件删除、注册变化和部分覆盖不得接受为新有效结果。
2. 作者路径：31 文件/120 实体专属工程，从书稿进入工具，过滤 error，定位 south 同名来源与 north related，Back 回原稿，处理更新后的选择与计数；鼠标与键盘分别记录。
3. 宽窄布局：1040×660、1280×800、1600×1000，暗/亮主题，16/28 字号，导航+参考+工具同时打开；记录可见路径、选中/焦点、正文空间、长说明滚动与截断。
4. 规模：至少 5000 问题，预热后 10 次不同组合查询、分页及布局，报告 p50/p95 与内存。offscreen 帧 p95≤40ms，查询/分页 p95≤50ms，报告构建≤5s；仅对固定本机 Rust 1.98 默认 dev（opt-level=0、debug=0、incremental=0、jobs=2）样本成立，不作为发行硬件承诺。报告+UI新增内存≤128MiB；若核心冻结更严门槛以更严为准。测量设备与实际配置必须一并记录，不能事后移动阈值。
5. 真实 native、offscreen、真实浏览器、系统 IME、读屏、高 DPI 分开标实测/未测。合成输入不能替代系统 IME；WASM 编译/协议不能替代浏览器 GUI；安全拒绝不得换端口/代理绕过。
