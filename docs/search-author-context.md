# 查找与作者位置（v0.13）

## 交互契约

- 查找只依据 core 对当前工程与唯一 `WritingBuffer` 的真实结果导航，不自行解析语言。每个文件仍只有一个正文缓冲，同源多章共享它；切换章节、模式及查找不会应用、保存或复制草稿。
- 结果列表的首项初始为“已选中、未定位”。第一次 Enter 定位首项，此后 Enter / Shift+Enter 才前后移动；查询、范围或真实稿版本变化会重置定位状态。空结果不改作者位置。
- 在当前写作、结构或源码模式能够准确表示整个命中范围时保留该模式。写作模式要求命中完全映射到同一个正文编辑块，结构模式要求整个范围位于该目标声明体。跨块、声明外或无效稿不能准确表示时切换同一缓冲的源码模式，并明确说明原因。
- 同源多个章节优先保留当前章；否则选择实际覆盖完整命中的已注册章节。跨文件命中使用该文件已有的唯一草稿；没有可承载该草稿的章节时拒绝导航并保留当前稿，不能改跳旧工程内容。
- 每次成功定位前保存完整作者入口：书稿、章 ID、目标、文件、显式模式、选区两端、滚动位置，以及它们绑定的源基线和真实缓冲代次。模式不是缓冲版本，旧焦点不是当前模式的选区。
- “返回”恢复仍有效的书稿/章/目标和模式；只有来源与缓冲版本完全相符时恢复旧选区及滚动。内容变化时保留现有稿，不套用旧偏移，并明确说明未恢复位置。目标或来源身份无法确认时保留当前入口并说明原因。
- Esc、关闭按钮及窗口关闭只收起查找并将焦点交给实际编辑区，不暗中撤销已确认导航。“返回”才负责回到先前作者位置。
- 输入法组合期间不执行 Enter 导航、快捷键查找或 Esc 关闭；事件级测试与原生/物理输入法验收分别报告。

## 实现与验证边界

UI 使用现有 core 的 `WritingBuffer::generation`、`project_writing_buffer` 与 `search_drafts`，不新增语言规则。位置只存元数据，不保存第二份可编辑正文。测试覆盖普通/Unicode 正文、结构与跨块回退、失效稿、同章/跨章/跨文件共享草稿、二次查询、空结果、Esc/关闭/返回、编辑后返回和输入法事件。事件级测试不替代原生窗口与物理输入法验收。
