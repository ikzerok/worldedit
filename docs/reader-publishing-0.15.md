# 0.15 读者发布流程契约

状态：0.15候选契约，需以当前代码完成验收。现行入口说明见 [发布静态读者包](reader-publishing.md)，视觉共同约束见 [视觉系统](visual-system-0.15.md)。公开选择、静态投影、路由、预算和失败规则以配对 worldline 的 `spec/reader-site.md` / `spec/reader-export.md` 为语义真源；UI 只使用核心 DTO 与计划。

## 一、两类输出及保存边界

完整工程导出保留工作区全部文件、未引用附件与作者资料。读者包只包含明确授权内容，是可离线解压阅读的静态站；拿到包的人可以读取包内全部内容，不提供在线账号、权限认证或故事执行 runtime。

应用配置、保存工程、生成审核包、临时预览、最终发布是不同动作：

- Profile 应用只改变 Project 内存并形成一次普通可撤销历史；“保存全部”才按原工作区规则持久化
- 原始 `.wl`、已注册展示文档、未知普通文件及未引用附件的完整工程保存规则不变
- Reader 预览/生成/取消不自动应用草稿、不清空输入、不推进工程保存基线
- 核心负责校验只读、未知能力、过期基线、冲突及恢复事务；UI 不绕过拒绝
- 发布确认始终对应当次审核内容，来源或选择变化后旧确认失效

## 二、四步向导

窗口固定显示当前步骤与底栏，主体有界滚动。取消与上一步始终清楚可达，不能要求滚完全部对象才能找到操作。

### 1. 选择内容

- 站点标题、配置选择/新建及对象、地图、章节、附件四类分组
- 按类型、名称、别名、ID搜索，显示候选数/匹配数/选择数
- 对象与地图图元按每页100条分页；全部匹配结果仍可访问
- “选择筛选结果”作用于全部匹配项，不是当前页；明确列出其范围
- 对象、字段、地图图元、章节、附件分别授权；批量对象选择不选属性字段
- v3 选择对象包含该对象全部别名及 typed 结构，界面与确认页说明这一点；property 仍逐键
- 地图包含 vector scene nodes 与旧 placements；选中组不自动选子项；底图引用的附件仍需明确选择
- 作者图层显隐不是公开权限；未公开引用不得泄露原 ID、路径或私有名称
- 静态条件/效果受限说明仅在明确勾选 `reader.story_details.v1` 时公开，不新做分支 runtime

### 2. 核对资源

显示核心计划的纳入条目、附件/静态文件、总字节、警告、排除原因及空页提示。排除明细只在作者窗口显示，不进入读者包。遇到失效选择明确失败并提供回到选择步骤的入口，不能悄悄缩小公开范围。

### 3. 预览页面

全部核心公开页面可检查，使用同一核心文本投影及生成 HTML/资源。搜索索引中每个主页面必须与 `output_path` 唯一对应，title/text 与预览一致；v3 额外地图锚点条目合法，不能简单按索引条目总数判错。

原生版提供显式“实际页面临时预览”入口，见异步物化约束。清楚标记临时预览不等于最终发布。此产品入口不能成为绕过工具 `file://` 安全拒绝的验收手段。

### 4. 确认生成

再次列明选择范围、别名/typed结构语义、静态说明开关和离线包边界。用户显式确认后才可发布 ZIP 或请求 Web 下载。桌面目标是工作区外、尚不存在的新文件；浏览器仅报告下载请求已启动，不宣称操作系统已保存成功。

## 三、Profile 保真

使用 `ReaderPublicationProfile` 和核心 create / preview-save / apply-save / preview / build API。已载配置更改选择时保留 routes；未再选中的旧route可以存留但不能泄露在输出中。保存可补新选择的受控route，不由UI自行造路由。

1. 已载配置中的缺失对象、字段、地图、节点、旧placement、raster、章节、附件不能在候选刷新时被 `retain` 静默移除
2. 不可用项单列，可分页、逐项明确移除；若未移除，下次核心预览仍须明确失败
3. `selection()` 不能只遍历当前候选而遗漏旧选择
4. 章节数组保留原阅读顺序，例如 `[chapter_z, chapter_a]` 不变成字母序；仍勾选旧项按原序，新选项按明确候选顺序追加
5. 其他列表的原配置顺序同样保留，不无故改写
6. v2 即便 fields 为空仍保留 `reader.fields.v1`
7. 未知 required_features 保留交给core拒绝，不能删掉后降级发布
8. 旧配置升级采用显式迁移预览/确认/取消，不因加载自动重写
9. 重新编译可刷新配置列表；当前已载配置不自动被另一版替换
10. 应用后明确提示尚需保存工程，失败或取消保留输入

### 配置计划与轻量前台提交

配置create与preview-save组合按后台任务执行，原生线程与Web同源Worker使用同一typed选择、原profile、ID及名称。返回计划必须精确匹配请求；原route只能保留并补充合法新route，不能被worker静默更换。零binary负载。

前台仍调用原apply-save完整重算计划，不接受worker任意after字节或整个Project替换。只有当前分析的active sources及compile_options与当前Project完全一致，且应用前后这两者不变时，才复用已有语言分析，更新正常历史、版本、地图缓存失效与配置菜单。源码/分析过期或表单外部冲突时拒绝应用并保留输入/计划；不能强行把旧分析标成新鲜。应用、撤销与重做不改runtime指纹，工程仍按原保存动作写盘。

2000对象固定规模必须测量消费Done到完成UI状态更新的整个前台路径，含完整core apply、scope/fresh核验、history与配置刷新，总耗时不超过250ms；不能只测core调用或把规划藏在spinner后。规划任务同样受窗口X与全局Close清理栅栏管理。

## 四、后台任务与审核一致性

审核、生成、ZIP编码、原生临时预览物化及最终交付均不得在主UI线程执行可随文件数/体积增长的长工作。目标为任务开始/取消/阶段变化250ms内可见反馈，提供阶段与完成量；以release测量验证，不能靠小fixture快就豁免。Profile 保存的同步计划路径须纳入测量，超过门槛则调整，不预先宣称达标。

所有结果携带或关联 generation、Project content baseline、selection、profile、plan digest。收到结果时重新比对；更改选择、源码、工程或取消后不得接受旧任务结果。审核文件集合使用共享不可变所有权，避免在点击临时预览时主线程克隆128MiB。

### Web worker

- 使用同源真实 Worker，经统一 `WorkerJob` / `WorkRequest` / `WorkEvent` / `WorkOutput` 接口
- 请求使用 有界 `Project::snapshot_files_limited(10000, 128MiB)` 加 `snapshot_state()`，不先无界捕获再限制；worker用精确snapshot state复原跟踪/删除/墓碑与baseline，不用刷新/迁移门槛不同的 `export_files()` 替代
- 资源用ArrayBuffer传输，禁止大资源JSON数组化
- 返回文件paths、raw_bytes、preview与binaries；前paths数量的binary对应文件，最后一项ZIP；数量、路径、预算、索引仍须主线程核验
- 先形成审核包，用户确认后再最终复核并下载；取消terminate，不写工程、不下载

### Reader ZIP

共享 `src/reader_zip.rs`；上限10000文件、128MiB原始内容和ZIP预算，安全UTF-8相对路径、64KiB分块取消、编码后逐项字节核对。不得借旧完整工程ZIP的4096文件/64MiB decoder静默缩小Reader能力；完整工程备份自身限制不因此改变。

## 五、原生临时页面预览

- 显式点击才启动，复制范围严格等于本次已审核安全文件集合，不复制工作区其他文件
- 私有唯一临时目录（Unix为0700），不启HTTP服务、不改安全边界
- 全部文件/每64KiB块可取消，有进度；任务只清理自己的目录
- 启动前比较 `reviewed.preview.content_baseline` 与当前Project baseline，同时比较selection/profile；缓存命中也经过该门
- 成功后再次核对baseline/digest/selection/profile，仍匹配才请求系统打开
- 通道Disconnected明确报告中断、清除busy并允许重试；不得用 `.ok()` 吞掉断线
- 取消、X关闭或工作区改变时，不请求打开；排队Done持有的目录在后台清理，UI不能同步删除大量文件
- 成功打开的目录保持到编辑器正常退出，不能关闭发布窗口就删掉浏览器仍使用的资源

## 六、最终原生交付与取消提交点

后台再次按核心计划复核审核digest；写入目标同目录私有临时文件，按块支持取消。以无覆盖原子公布提交最终目标，已有目标永不覆盖；不采用可能覆盖目标的rename。只清理本任务临时文件，Windows清理前关闭句柄。

取消在提交点之前可以获胜并保证没有部分目标；进入原子提交阶段后必须等待真实结果，不能声称已撤销，也不自动删除已成功公布的目标。明确区分取消成功、发布成功与错误，保存基线不受影响。

## 七、同帧X与排队完成

窗口一帧中必须先读取并处理关闭/取消意图，再消费会应用配置或触发浏览器打开/Web下载的完成结果。不能在绘制X之前先poll完成。鼠标按下待释放期间也不能让完成越过潜在X/取消动作。

Escape与X需分别验证；上层临时窗口关闭、嵌套输入与IME规则沿用工作区契约。原生已经跨提交点的发布按上一节处理，不要求取消已完成发布。
