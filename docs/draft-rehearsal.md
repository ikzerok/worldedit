# 不应用正文，先隔离试演

在书稿或试玩页选择「试演当前正文草稿…」。编辑器在后台核对已应用工程和当前全部
已改变的正文文件草稿；每个源文件只纳入一份，同源章节共用这份 WritingBuffer。
至少需要一份真实改变的活动源草稿。确认页列出实际纳入的文件、草稿代次、完整源码
范围及排除的未提交表单；核对 seed 后明确开始。取消准备不会改正文、工程保存状态
或普通试玩。

Focus 和紧凑书稿保留正文空间：小窗口从「书稿工具」进入，宽窗口从「试演」菜单进入同一草稿核对。
进入试演后，小窗口用「试演操作」重新试演、切回已应用稿或关闭；下拉选项切换正文、状态、条件和输入范围。

「正文与选择」展示这次真实运行的新文字、实际选项和不可选原因；暂停、继续、
步数/时间预算只影响隔离快照。「状态与变化」可查全局、调用局部和状态集，比较
首次/上次真实观测并分页；「实际条件证据」展示本次求值和声明来源，不用终值猜原因。
入口遵守作品原有执行入口，不从任意章跳过初始化。

有可确认的初始作者位置，且章节、源文和草稿代次仍一致时，「返回原草稿位置」恢复
原章节、编辑模式、选区和滚动。若从试玩页发起时没有可确认的书稿位置，可从本次证据
定位来源，或自行回书稿继续；不会按相似位置代替。状态/条件中的来源动作经过同一
快照校验后定位真实声明头，Alt+Left 返回试演。编辑之后旧会话清楚标记
过期，仍保留只读证据；继续选择和回源须明确重新试演。不会把暂停中的 Story
偷偷换成新稿，也不会用相似 choice 标签接续旧路线。

普通试玩保留在原处。「保留试演，查看已应用稿」可切回原会话；「返回隔离试演」
再切回来。关闭试演释放它自己的后台会话。停止正在进行的后台动作仅保留已经
收到的证据，不承诺获得未返回的部分状态。

## 从草稿验证到正式记录

1. 写正文，暂不应用
2. 核对范围并试演，查看实际状态/条件
3. 返回原稿修改，需要时明确重新试演
4. 通过书稿既有按钮明确应用正文
5. 从新的已应用稿开始普通试玩，再录制正式路径

草稿模式没有正式游戏保存、检查点或路径导出入口。已有 strict replay 与检查点
指纹守卫不变。未应用表单、导入候选、未创建事件不会自动参与；正文组合输入或
未插入的保留正文须先处理，无法确认当前稿时不拿旧版本替代。

## 预算与平台边界

草稿最多256个文件、前后源文16MiB；完整活动源最多4096文件/64MiB。单次界面
推进最多100000步/250ms，可降低到零立即暂停。单会话实际输出最多1MiB/32768项，
真实状态与条件证据另有预算；完整后台响应最多8MiB。超额明确停止，不截断后称完整。

原生使用独立线程；不可抢占的编译取消后会完成并丢弃结果，同进程最多一个这种
编译。新准备在原任务退出前等待，不叠加完整工程副本。浏览器使用随静态包分发的
同源持久Worker，关闭即终止；Worker保有一份真实core/runtime会话，主线程不再次
编译。浏览器工作区仍是授权导入的快照，外部磁盘改变需重新导入。

发布验证提供 `scripts/test-draft-rehearsal-worker.mjs <最终Web目录>`，以真实Node
Worker载入最终WASM验证协议、真实运行、来源与释放/重开。此测试不证明浏览器
同源加载、CSP/CORS、实际浏览器交互、物理输入法或跨源隔离；这些须单独实测。
