# 同稿 schema 快照（0.35）

本产品契约先于实现；语言和事务规则以同级 worldline 的
`spec/schema-authoring.md`、`spec/schemas.md` 为准，编辑器不重写判定器。

## 已应用稿与未应用输入

约束源码工作台和四类资料表单读取当前已应用工程的同一次编译结果。
schema 索引直接从这次编译的声明和正式诊断生成，不再次编译或验证。
单对象投影按完整 TargetRef 缓存，不能只用显示名或裸 ID；切换对象不重新
编译，返回已访问对象时复用其投影。缓存有界，淘汰只影响只读投影，不丢弃表单输入。

未应用的源码、字段或绑定输入不会改变这份已应用快照，也不会因绘制、滚动、
折叠、主题或五种布局的变化触发语义编译。显式预览仍调用 core 检查候选稿；
预览成功不代表已应用或已保存。

## 失效与平台边界

真实源码或编译能力变化后，既有工程编译链建立新的快照并清空旧投影缓存。
纯展示文档更新可以保留编译结果和 schema 索引，但必须更新事务基线，旧表单
仍须经过 core 的新预览和应用守卫。来源、工作区身份或内容基线不匹配时，
旧投影不得被当作当前稿返回；原输入保留，界面显示需重新载入或预览的理由。

schema 读取复用已经完成的同步工程编译，不另启动竞争的索引后台任务。
因此没有异步结果覆盖新对象或新稿的发布入口；读取和诊断刷新不请求输入焦点、
不改变光标。现有首次加载和真实改稿编译仍有同步成本，须单独测量，不能用
暖缓存耗时宣称首次建立或任意规模实时响应。若将来增加后台构建，必须同时
校验工作区、内容基线、任务代次和目标身份，单飞且可废弃，过期结果只丢弃。

native 与 WASM 共用此读取和失效规则。桌面沿用现有外改检测及冲突保护；
浏览器仍读取完整导入快照，外部磁盘变化须重新导入，不声称持续磁盘监视。

## 有限性能验收

自动测试记录编辑器语义编译入口计数和单对象投影构建次数。约束窗口连续
至少 120 个空闲、滚动或折叠帧，主题及布局切换后，语义编译计数不增加；
同稿对象往返的已缓存投影不重建。另检查 schema 绘制路径没有独立编译入口。

release 的忽略型探针使用新造 1,000 / 10,000 实体及其绑定，另有同名跨 kind
人物对照，列出源码字节、
schema、字段与绑定数，分别记录首次载入、单字段预览和应用后的完整重建、同稿对象
切换、外部源码刷新后的重建及 120 帧绘制总耗时。同步调用的耗时即该调用的
主线程占用，不把它冒充整帧或原生输入延迟；真实系统交互和浏览器端到端
时延仍须在相应平台单独验收。
