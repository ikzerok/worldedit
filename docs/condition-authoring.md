# 条件创作

条件表单适用于已有事件中的三处：分支的显示条件、可选条件，以及事件的前置条件 after。它读取当前事件表单里的条件；不会自动应用其他草稿，也不会自动升级语言版本。

## 修改已有条件

1. 在事件详情展开分支，或找到“前置要求 / 准入条件”
2. 修改已有状态、标签、全局布尔变量或变量与字面量的比较。候选来自实际已声明对象，可以搜索并分页，完整 ID 与所属对象区分同名资料
3. 用“调整子句”添加取反、AND、OR，或明确保留某一项。左、右子项和每层分组单独显示；不自动排序、合并或改变求值顺序
4. 点“预览条件改动”核对原条件和修改后条件，再“应用到事件草稿”。“取消条件输入”只取消尚未确认的条件表单输入
5. 点事件的“应用更改”进入工程内存；最后保存工程。全局的“输入待应用”和“工程待保存”是不同状态，可以同时存在

可选条件需要显式语言 1.12 或更新版本，并且必须填写禁用说明。条件和说明暂未成对时，输入会保留，事件应用会等待配对完成。保存不会替你完成或暗中应用这份输入。

支持的表单子集是布尔常量、全局 bool 变量、已声明 state 包含 tag、全局 num/str/bool 变量与同类型字面量的合法比较，以及 not/and/or。字符串框输入普通文字；引号与反斜杠的源码转义由核心处理。状态定义旁的入口可回到准确声明，或打开所属对象的真实运行旁查；作者条件与运行证据分别显示。

复杂表达式、含内部注释的条件、无效条件与超出预算的条件显示完整高级源码，不生成可修改的部分树。源码入口仍保留全部内容；可以显式编辑完整条件或其中的注释，无修改时原字节不变。表单限制为 128 节点、24 层、16 KiB 条件源码；限制不是语言表达能力的承诺。预览不求值，不消耗随机数。

若来源、工程基线或事件正文在编辑期间变化，旧条件输入会保留并阻止应用。先取消该旧条件输入，再从当前稿重新读取；不要把旧预览当成已写入工程。输入法组合期间文字框继续接收文字，预览、应用与结构切换等动作等待组合完成。
