# 从变量终值回到实际写入

路线对照现在可以回答：“两条真实路线里，这个全局变量实际被写过几次，每次从什么变成什么？”

入口仍是试玩页的“路线对照”。先录制或导入两条真实路径，再显式选择“比较当前已应用稿”。
查看结果不会推进普通试玩、应用作者草稿或保存作品。

## 选择变量

“变量终值与实际写入”列出两侧保留的全局变量终值。单击变量名，或用 Tab 到达后按 Enter，
即可查看这个变量的实际写入。终值相同的变量也可以选择，因为相同终值并不代表相同写入过程。
未发生本段写入的起点变量也会保留在终值卡中。

- A、B 和路径名称表示当前呈现的两侧；“交换 A/B”不会改变记录所属的实际路径
- 每条写入显示真实顺序号、`let` / `const` / `set`、变量名、写入前后值、节点与回合
- 顺序号属于该侧本段全部变量写入；按变量筛选后编号可以有间隔，不会重新编号
- “未初始化”表示当时尚无该全局变量，不等于空字符串、false 或 0；值旁会显示类型
- 同值写入明确标注“值未改变，仍实际执行了这次写入”
- 长值按 Unicode 字符截断并明确标注，可展开“查看完整值”或复制完整内容

例如，A 实际执行 `set coins = 1`、`set coins = 1`、`set coins = 0`，
B 执行 `set coins = 10`、`set coins = 0`。两侧终值均为 0，A 仍有三次实际写入，
其中第二次是同值写入。界面不会用终值倒推或补造这些动作。

## 阅读证据边界

每侧同时显示路线状态、捕获状态与保留情况，请一起阅读：

- “旧结果未提供变量写入证据”不是“没有写入”。尚未建立验证实例即取消或失败，也没有该证据
- 只有该侧本段验证完整、已开启捕获且变量写入未省略时，才会明确说本段没有对所选变量写入
- 步数、时间、输出预算、取消、运行失败或原路径分歧只显示实际停止前的已知记录
- 状态动作与变量写入共享每侧最多 256 条 / 64 KiB；超过上限时显示实际总数、保留数及省略说明
- 单个字段或来源过长也可能被省略。缺少保留记录不能解释为没有发生
- 顶层初始化与检查点继承值属于起点，不回填成新历史；片段参数与 `local` 不属于全局写入
- 未执行的条件分支和未选选项不会出现。`const` 重访被跳过时不生成假写入

这是本次验证区段的执行证据，不是完整因果图、局部变量调试器或永久历史。

## 回到作者来源，再返回

使用“打开实际写入来源”定位实际执行的 `let` / `const` / `set` 语句头。
跨文件、嵌套场景与共享片段的来源由语言内核确认；界面不会按变量同名或最初声明猜测。
没有可确认来源时仍可阅读值与动作，来源按钮会禁用并显示说明。

Alt+Left 返回同一路线对照，恢复所选变量、具体写入、滚动与焦点。
交换 A/B 后仍沿用记录的真实侧身份。重新比较会创建新结果，旧写入即使序号相同也不会被冒认。

未应用执行草稿、输入法组合、工作区冲突、当前编译错误、源码或清单外改、源位置移动，
都会阻止不可信的来源跳转。它不会为了跳转自动保存、丢弃输入或偷偷刷新工程。
桌面可检查磁盘基线；浏览器只检查导入快照，无法观察尚未重新导入的宿主磁盘变动。
