# 外部改稿之后继续写

工作区文件被其他编辑器或协作者改动，同时本地仍有未保存内容时，worldedit 会保留
本地稿并提示冲突。点击“查看冲突差异”进入外部改稿材料。

## 从三方原文到明确候选

1. 先核对准确文件路径。保存基线是上次保存的字节，本地缓冲是已应用但未保存的内容，
   捕获磁盘是本次读到的外部文件。缺失与空文件分别显示
2. 大窗口并排看三方；小窗口切换“保存基线 / 本地缓冲 / 捕获磁盘”。每一方可以滚动
   阅读、选择复制。原始非 UTF-8 字节按段查看十六进制，原文件不会转换
3. 对每个文件明确选择一侧、明确删除，或输入手工全文。手工候选为空时可先载入某一侧；
   有输入后这些载入按钮不会直接替换它。不会自动猜测合并，也没有默认的获胜一侧
4. 点击“预览候选”，核对所有文件的候选全文、未解决数量和完整工程问题。修改候选后
   旧预览立即失效，需要重新检查
5. 全部受保护条件满足后点击“采纳到内存”。core 再次核对实际工作区及完整候选。
   成功后关闭材料窗口，继续写、撤销或明确“保存全部”

采纳只改变当前工程内存，磁盘保存另行执行。选择磁盘版本可能使文件变干净，选择本地
或手工版本通常仍是未保存稿。更早代次的撤销历史失效，本次采纳留下一个撤销步骤；
撤销回到采纳前本地内容，同时保留刚核验的磁盘保存基线。保存后再撤销仍是新的未保存稿。

## 取消、草稿与过期

“关闭并保留”或 Escape 返回原稿，保留三方材料、侧选择与手工输入；重新打开同一工作区
可以继续。检查期间可“停止检查”，不会部分采纳。上一轮线程尚在释放资源时不会再叠加
后台任务。

源码输入法、未应用正文 WritingBuffer、地图与对象表单等未提交输入会阻止采纳。先回到
这些输入自行处理；worldedit 不替你应用、覆盖或清空草稿。仅查看和预览不会改变它们。

磁盘或当前 Project 在捕获后又变了，旧候选会被拒绝。输入保留，明确重新捕获后再核对；
重新捕获不自动沿用旧侧选择。遇到尚未刷新到工程的新增源码或无本地修改文件时，先关闭
材料让工作区刷新，再重新捕获。保存之后发生另一轮外改，保存守卫仍拒绝覆盖。

## 未完成正文与保护边界

此入口处理已跟踪源码与已注册 JSON 中，本地和磁盘都相对保存基线改变的冲突。普通
未注册 JSON 和附件只参与完整磁盘变化守卫，不在这里合并。一次扫描最多4096文件，
磁盘证据和缓冲证据分别受64MiB预算约束，单个输入最多16MiB；超额会拒绝，不能用
截断材料采纳。

普通 `.wl` 语法/语义错误会完整列出。若当前需要保留未完成稿，可明确勾选“保留为未完成
源码”；结果仍标为不可运行，不会伪称编译通过。已注册文档错误、未知能力/格式、无效原始
字节、文件身份不明、只读目标、未完整核验或超预算仍然阻断，不能靠此勾选豁免。

遇到这些保护，保留原材料并使用原有另存工程副本或事务救援入口。普通外改处理不能清理
`.transactions`、不能解决未完成保存事务、不能推测未知字段的合并。选择某一侧保留其完整
原始字节；手工全文完全以你明确输入的候选为准。

浏览器工作区是导入快照，没有持续磁盘读取权限。浏览器没有假造的外改监视入口；需要
重新导入实际外改材料，同一 core 的来源与字节保护依然适用。

保留的手工候选和明确侧选择也计入未应用输入。即使之后把工程正文改回干净状态，切换
工程或退出仍会提示；“回到草稿”回到原材料和手工文字，只有明确选择丢弃未应用输入才会
清除。采纳本组候选不会被本组自己的提示自我阻挡，其他未应用正文/表单仍须先处理。
