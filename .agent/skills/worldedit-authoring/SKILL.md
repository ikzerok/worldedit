# 使用 worldedit 完成创作

## 确认作品与工具

先确定用户正在创作的工作区绝对目录和根入口 `world.wl`。已有目录沿用，不把编辑器安装目录或 worldline 源码仓库当作作品目录。目录内递归索引全部 `.wl`，用子目录分区；参考笔记用 Markdown，附件放入目录再引用。对尚未确定的工作区，先询问作品位置再写入。

查找已安装的 `wl`、`wl-agent`、`worldedit`；源码环境中可用 `cargo run --manifest-path <worldline>/Cargo.toml -p wl -- ...`。查看 [CLI 能力表](../../../docs/cli-coverage.md) 区分文件创作与窗口操作。仓库布局下语言规范在同级 worldline 的 [规范索引](../../../../worldline/spec/README.md)，首次写作阅读 [创作手册](../../../../worldline/docs/handbook.md)；发行包从随包的 worldline/spec 与 worldline/docs 读取。复制本技能到作品后，应按实际安装目录定位这些文档，不假设复制后的相对链接仍成立。

## 读取上下文并提醒关联

先运行 `wl check "工作区目录" --json` 和 `wl catalog "工作区目录" --json`，阅读相关源文件。按名字、稳定 ID 和别名查找全部候选；同名对象分别确认身份。查看关系时调用 graph，涉及时段或先后时调用 timeline。修改前明确要改的对象与现有基线诊断。

创作时主动告诉用户与当前改动直接相关的既有内容，带对象 ID 和源文件位置：

- 人物：已有别名、动机、关系、出现事件、正文链接及关联状态。
- 事件：上游选择、显式条件、目标准入、人物引用、效果、所属时段和 follows。
- 状态：初始标签、with/add/remove 的区别、哪些分支会改变它、哪些要求读取它。
- 锚点：关联的人物、事件和状态，修改是否影响叙事意义与变化出处。
- 附件与分类：素材的实际文件、使用对象、标签直接与递归命中。

提醒应简短并针对实际证据。例如“改变 mood 初值会影响 gate 的准入，另一个分支在 warning 中移除 alert”。把新创意标为提议，把源码事实与运行后事实分开。工具不检查自然语言矛盾；无法从现有资料确定的关联应说明不确定，不编造隐藏设定。不为普通一致性提醒增加重复审批。

## 写作与修改

把所有输出写到已确定的工作区内。include、asset 和文件对象引用均使用声明文件位置的相对路径。外部素材需先复制进目录并确认复制成功；不建立目录外链接或绝对文件引用。

按用户要求直接完成创作，保留已有稳定 ID、其他分支和注释。新增 ID 先检索重复；改 ID 时检查结构引用、别名、正文链接、状态、锚点与关系，不做不加区分的全文替换。普通正文同名提及不是自动引用。

人物静态资料写 property；动态事实写 state；数值用 let/set。身份用状态标签，新创作不再引入 grant/revoke/perm。事件效果分别表达 enter、exit、done；跳转不会触发 done。用 follows 写实际时间偏序，卡片排序 at 只改变展示。

CLI 没有编辑器远程控制 API。可直接编辑磁盘 `.wl`，由桌面自动刷新；操作前注意编辑器是否有同文件未保存内容，发生冲突先保留双方并合并。需要切换视图、检查画面、拖动布局、撤销或导出时，使用可用的真实 UI 工具完成，并观察结果。没有 UI 工具时明确报告该操作尚未执行，不伪造窗口已同步或导出已成功。

## 验证与交付

改稿后对整个工作区重新 check、catalog，并检查受影响的 graph/timeline。完成条件是新增结构错误清零，相关对象和引用可定位；旧问题单独说明，不静默删除用户内容以消除报错。

用户需要可玩故事时，演练受影响的选择、准入和状态路径。人类 play 选择序号从 1 起，JSON 使用返回的 index 从 0 起。有状态自动化用 wl-agent，每行一个 JSON-RPC 请求；先 initialize，再 compile，再以返回的 story_id 建立 session。存档不是工程备份，改稿后的指纹不匹配要报告，不能绕过。

用户请求交付时通过编辑器导出到工作区外的新目录，验证所有文件、附件、隐藏创作资料都在，重新 check 导出目录。`wl-agent export` 只返回 Mermaid，不是工程导出。最终说明写了什么、关联提醒、实际验证路径和未完成事项；不要把未演练分支宣称为通过。
